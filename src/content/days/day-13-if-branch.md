## 오늘 배울 이유

점수가 기준을 넘었는지에 따라 실행할 일을 갈라야 합니다. Day 13 "`조건문으로 경로 선택`"에서는 Python 코드의 실행 결과(`목표 달성`)를 따라가며, `조건에 따른 한 경로 선택` 동작이 왜 필요한지 확인합니다. 이 동작이 빠지면 "`들여쓰기를 지워 else 블록도 실행될 거라 생각함`" 같은 문제가 생깁니다.

## 시작 전에 확인할 것

바로 앞선 [Day 12](/learn/day-12-comparison)에서 배운 "값 비교와 경계 포함" 내용을 한 문장으로 말해 보세요. 이번 "`조건문으로 경로 선택`"에서 새로 달라지는 조건을 찾아보세요. 핵심 표현은 `>= 30`입니다.

## 머릿속 그림

if는 조건이 참인 블록만 실행하고 else는 거짓일 때만 실행합니다. 두 블록을 동시에 실행하지 않습니다. Day 13에서는 아래 흐름 순서대로 상태가 바뀌고, 결과를 가르는 부분은 `>= 30`입니다.

```text
minutes=45  →  조건 참  →  목표 달성
```

위 흐름에서 `>= 30` 부분이 실행되는 지점을 찾으면 읽는 값과 바뀌는 값이 나뉘어 보입니다. 마지막 출력은 `목표 달성`입니다.

## 천천히 풀어보기

조건문은 두 길 중 실행할 길을 하나 고릅니다. `if minutes >= 30:`이 참이면 들여쓴 첫 블록으로, 거짓이면 `else:` 블록으로 갑니다. 30은 참 쪽에 들어가고 29는 거짓 쪽에 들어갑니다. 실행하지 않은 블록의 `print`는 아예 호출되지 않습니다.

들여쓰기는 꾸미기가 아니라 어느 줄이 어느 갈래에 속하는지 정합니다. 예를 들어 조건 밖으로 `print("완료")`를 빼면 어느 쪽을 택해도 출력됩니다. 29, 30, 31을 각각 넣고 실행 순서를 종이에 화살표로 그려 보세요.

## 문법을 예제로 보기

아래 Python 코드는 Day 13 "`조건문으로 경로 선택`"의 독립 예제입니다. 전체 5줄 가운데 핵심 부분은 `>= 30`이며, 실행 결과는 `목표 달성`입니다.

```python
minutes = 45
if minutes >= 30:
    print("목표 달성")
else:
    print("조금 더")
```

예상 출력:

```text
목표 달성
```

하단 Python 실행 영역에 같은 코드가 들어 있습니다. 먼저 실행 결과(`목표 달성`)를 가리고 예측한 뒤 실행해 비교하세요.

2. 45>=30이 참입니다
3. if 블록을 출력하고 else 블록은 건너뜁니다

`>= 30` 부분이 실행될 때 읽는 값과 바뀌는 값을 한 줄씩 적어 보세요. 다음 `결과 예측과 작은 변경`에서는 이 부분이 달라집니다.

## 자주 틀리는 지점

**확인할 실수: 들여쓰기를 지워 else 블록도 실행될 거라 생각함.** 정상 코드의 실행 결과는 `목표 달성`입니다.

- 정상 줄: `if minutes >= 30:`
- 잘못된 줄: `if minutes < 30:`

두 줄을 나란히 놓고 `if는 조건이 참인 블록만 실행하고 else는 거짓일 때만 실행합니다. 두 블록을 동시에 실행하지 않습니다.` 기준으로 어느 쪽이 맞는지 설명하세요. 결과가 예상과 다르면 `minutes=45`부터 `목표 달성`까지 처음 어긋난 곳을 찾습니다.

## 다른 언어로 옮기기

세 언어에서 지켜야 할 핵심 동작은 `조건에 따른 한 경로 선택`입니다. 목표는 같은 입력에 같은 결과를 내는 것으로, 각 언어의 규칙에 맞게 옮겼는지 실행 결과로 대조하세요.

| 언어   | 옮길 때 확인할 표현과 규칙    |
| ------ | ----------------------------- |
| C17    | if (...) { ... } else { ... } |
| Python | if 조건: 들여쓰기 else:       |
| Rust   | if 조건 { ... } else { ... }  |

C17에서는 `if (...) { ... } else { ... }` 규칙을 적용합니다. "`조건문으로 경로 선택`" 수업의 실행 결과(`목표 달성`)를 기준으로 삼고, C는 범위와 널 검사를 자동으로 해 주지 않으므로, 코드에 사용된 접근마다 유효 범위를 직접 확인해야 합니다. Python에서는 `if 조건: 들여쓰기 else:` 규칙을 따릅니다. 실패나 빈 입력은 예외로 드러내며 조용히 넘기지 마세요. Rust에서는 `if 조건 { ... } else { ... }` 규칙을 따릅니다. 실행 결과가 다르면 컴파일 오류(타입, 소유권, 빌림)와 실행 때 패닉(인덱스 범위 등) 중 어느 쪽인지 메시지부터 구분하세요.

## 실습 순서

예측(`목표 달성` 맞히기) → 빈칸(`>= 30` 채우기) → 변경(`처음 등장하는 숫자를 45에서 46로`) → 오류 수정(`들여쓰기를 지워 else 블록도 실행될 거라 생각함` 찾기) → 독립 구현(`조건문으로 경로 선택을 보여 주는` 만들기) 순으로 진행하세요. 각 단계의 답은 본문의 `목표 달성` 및 `>= 30` 설명과 대조하세요.
