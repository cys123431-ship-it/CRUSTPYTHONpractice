## 오늘 배울 이유

가장 최근 작업부터 되돌리는 실행 취소는 스택의 후입선출 순서와 같습니다. Day 58 "`실행 취소에 스택 적용`"에서는 Python 코드의 실행 결과(`삭제`)를 따라가며, `최근 작업부터 되돌림` 동작이 왜 필요한지 확인합니다. 이 동작이 빠지면 "`pop(0)으로 가장 오래된 작업을 먼저 제거함`" 같은 문제가 생깁니다.

## 머릿속 그림

append는 위에 쌓고 인자 없는 pop은 맨 위의 최신 작업을 제거해 돌려줍니다. Day 58에서는 아래 흐름 순서대로 상태가 바뀌고, 결과를 가르는 부분은 `pop()`입니다.

```text
[]  →  [입력]  →  [입력,삭제]  →  삭제 pop
```

위 흐름에서 `pop()` 부분이 실행되는 지점을 찾으면 읽는 값과 바뀌는 값이 나뉘어 보입니다. 마지막 출력은 `삭제`입니다.

## 천천히 풀어보기

실행 취소를 만들 때는 가장 **최근** 작업부터 되돌려야 합니다. 작업 A 다음 B 다음 C를 쌓았다면 취소 순서는 C, B, A입니다. Python 리스트의 `append`는 끝에 쌓고 인자 없는 `pop()`은 끝의 값을 꺼내므로 이 순서에 맞습니다.

빈 스택에서 `pop()`을 부르면 오류가 납니다. '취소할 작업 없음'을 미리 검사하세요. 스택 안에 작업 이름만 넣을지, 이전 상태까지 넣을지도 중요합니다. 실제 편집기는 이전 값을 되살릴 정보를 쌓아 두어야 취소가 가능합니다.

실행 취소를 만들 때는 가장 최근 작업부터 되돌려야 합니다. 작업 A 다음 B 다음 C를 쌓았다면 취소 순서는 C, B, A입니다. Python 리스트의 `append`는 끝에 쌓고 인자 없는 `pop()`은 끝의 값을 꺼내므로 이 순서에 맞습니다.

빈 스택에서 `pop()`을 부르면 오류가 납니다. 취소할 작업 없음을 미리 검사하세요. 스택 안에 작업 이름만 넣을지, 이전 상태까지 넣을지도 중요합니다. 실제 편집기는 이전 값을 되살릴 정보를 쌓아 두어야 취소가 가능합니다.

## 문법을 예제로 보기

## 핵심 줄 따라 읽기

예제의 핵심 표현은 `pop()`입니다. 아래 줄 번호가 붙은 코드에서 이 표현이 있는 줄 번호를 말하고, 그 줄이 읽는 값과 바꾸는 값을 적어 보세요.

```python

 3 | history.append("삭제")

```

1. 입력을 저장합니다
2. 그 위에 삭제를 쌓습니다
3. pop이 삭제를 반환하고 입력은 남습니다

`pop()` 부분이 실행될 때 읽는 값과 바뀌는 값을 한 줄씩 적어 보세요. 다음 `결과 예측과 작은 변경`에서는 이 부분이 달라집니다.

위 순서대로 실행한 최종 출력은 `삭제`입니다. `[]` 단계와 마지막 단계를 비교하면 입력과 출력의 관계가 보입니다.

작업 A를 하고 B를 한 뒤 `undo.pop()`을 부르면 B가 나와야 합니다. `['A','B'] → ['A']`로 남고, 한 번 더 취소하면 A가 나와 빈 목록이 됩니다. 이미 빈 스택에서 또 취소한다면 오류를 그대로 보여 주기보다 '취소할 작업 없음'이라는 동작을 정해야 합니다.

## 시간과 공간 복잡도

실행 취소 기록을 리스트 끝에 쌓으면 추가와 되돌리기가 평균 O(1)입니다. 중간에 끼워 넣지 않고 끝에서만 다루기 때문입니다. 기록이 n개면 공간은 O(n)입니다. 빈 기록에서 되돌리기를 부르면 항목이 없으므로 먼저 비었는지 확인해야 합니다. Day 58의 핵심 연산을 위 기준으로 직접 세어 보세요.

## 결과 예측과 작은 변경

원본 실행 결과는 `삭제`입니다. 아래 코드에서 원본과 달라지는 첫 줄을 표시하고, 그 줄의 변경 전후 값을 적어 보세요.

```python
history = []
history.append("입력!")
history.append("삭제")
print(history.pop())
```

찾은 줄을 적용했을 때의 실행 결과를 먼저 예측해 보세요.

해설: 바뀐 코드의 실행 결과는 아래와 같습니다.

```text
삭제
```

원본과 수정본 모두 `삭제`를 출력한다. 꺼내는 값은 마지막에 넣은 삭제 그대로이므로 출력이 같습니다. 바뀐 것은 먼저 쌓은 값뿐이고 꺼내는 쪽은 그대로이므로 중간 상태가 달라졌다고 쓰지 않는다.

## 자주 틀리는 지점

**확인할 실수: pop(0)으로 가장 오래된 작업을 먼저 제거함.** 정상 코드의 실행 결과는 `삭제`입니다.

- 정상 줄: `print(history.pop())`
- 잘못된 줄: `print(history.pop(0))`

두 줄을 나란히 놓으면 정상 줄 `print(history.pop())`이 `append는 위에 쌓고 인자 없는 pop은 맨 위의 최신 작업을 제거해 돌려줍니다.` 설명과 맞고, 잘못된 줄은 `pop(0)으로 가장 오래된 작업을 먼저 제거함` 쪽으로 어긋납니다. 결과가 예상과 다르면 `[]`부터 `삭제`까지 처음 어긋난 곳을 찾습니다.

## 다른 언어로 옮기기

세 언어에서 지켜야 할 핵심 동작은 `최근 작업부터 되돌림`입니다. 목표는 같은 입력에 같은 결과를 내는 것으로, 각 언어의 규칙에 맞게 옮겼는지 실행 결과로 대조하세요.

| 언어   | 옮길 때 확인할 표현과 규칙  |
| ------ | --------------------------- |
| C17    | 배열 끝 top과 용량 검사     |
| Python | list.append/pop()           |
| Rust   | Vec::push/pop은 Option 반환 |

C17에서는 `배열 끝 top과 용량 검사` 규칙을 적용합니다. "`실행 취소에 스택 적용`" 수업의 실행 결과(`삭제`)를 기준으로 삼고, C는 범위와 널 검사를 자동으로 해 주지 않으므로, 코드에 사용된 접근마다 유효 범위를 직접 확인해야 합니다. Python에서는 `list.append/pop()` 규칙을 따릅니다. 실패나 빈 입력은 예외로 드러내며 조용히 넘기지 마세요. Rust에서는 `Vec::push/pop은 Option 반환` 규칙을 따릅니다. 실행 결과가 다르면 컴파일 오류(타입, 소유권, 빌림)와 실행 때 패닉(인덱스 범위 등) 중 어느 쪽인지 메시지부터 구분하세요.

## 실습 순서

예측(`삭제` 맞히기) → 빈칸(`pop()` 채우기) → 변경(`첫 문자열을 '입력'에서 '입력!'로`) → 오류 수정(`pop(0)으로 가장 오래된 작업을 먼저 제거함` 찾기) → 독립 구현(`'실행 취소에 스택 적용' 개념을 보여주는 작은 프로그램` 만들기) 순으로 진행하세요. 각 단계의 답은 본문의 `삭제` 및 `pop()` 설명과 대조하세요.
