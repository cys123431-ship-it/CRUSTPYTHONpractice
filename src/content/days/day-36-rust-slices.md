## 오늘 배울 이유

배열 일부를 복사하지 않고 읽을 때 시작·끝 인덱스의 의미를 정확히 알아야 합니다. Day 36 "`Rust 슬라이스와 범위`"에서는 Rust 코드의 실행 결과(`20 30`)를 따라가며, `복사 없이 부분 범위를 빌림` 동작이 왜 필요한지 확인합니다. 이 동작이 빠지면 "`끝 인덱스 3도 포함한다고 생각함`" 같은 문제가 생깁니다.

## 시작 전에 확인할 것

바로 앞선 [Day 35](/learn/day-35-ownership-review)에서 배운 "주소와 소유권 회상" 내용을 한 문장으로 말해 보세요. 이번 "`Rust 슬라이스와 범위`"에서 새로 달라지는 조건을 찾아보세요. 핵심 표현은 `1..3`입니다.

## 머릿속 그림

슬라이스 [1..3]은 시작 1을 포함하고 끝 3은 제외하므로 원소 20,30을 빌립니다. Day 36에서는 아래 흐름 순서대로 상태가 바뀌고, 결과를 가르는 부분은 `1..3`입니다.

```text
[10,20,30,40]  →  [20,30] 빌림  →  20 30
```

위 흐름에서 `1..3` 부분이 실행되는 지점을 찾으면 읽는 값과 바뀌는 값이 나뉘어 보입니다. 마지막 출력은 `20 30`입니다.

## 천천히 풀어보기

슬라이스는 배열이나 Vec의 원소 일부를 **소유권 없이 잠시 보는 창**입니다. `[10,20,30,40]`에서 `[1..3]`은 1번을 포함하고 3번은 제외하므로 20과 30입니다. `[0..0]`은 아무 원소도 없는 빈 슬라이스입니다.

슬라이스의 끝은 길이까지 지정할 수 있습니다. 길이 4에서 `[1..4]`는 20,30,40이지만 `[1..5]`는 범위 밖입니다. 슬라이스를 빌려 쓰는 동안 원래 Vec를 재할당할 수 있는 `push` 같은 수정은 제한됩니다. 창이 바라보는 장소가 중간에 바뀌지 않게 하려는 규칙입니다.

## 문법을 예제로 보기

아래 Rust 코드는 Day 36 "`Rust 슬라이스와 범위`"의 독립 예제입니다. 전체 5줄 가운데 핵심 부분은 `1..3`이며, 실행 결과는 `20 30`입니다.

```rust
fn main() {
    let values = [10, 20, 30, 40];
    let middle = &values[1..3];
    println!("{} {}", middle[0], middle[1]);
}
```

예상 출력:

```text
20 30
```

Rust는 `rustc --edition=2024` 또는 Cargo로 실행하면 실행 결과는 `20 30`입니다. 브라우저에서는 임의 컴파일 대신 하단 실습 칸의 답안 비교를 사용하세요.

## 핵심 줄 따라 읽기

예제의 핵심 표현은 `1..3`입니다. 아래 줄 번호가 붙은 코드에서 이 표현이 있는 줄을 찾으세요.

```rust
 1 | fn main() {
 2 |     let values = [10, 20, 30, 40];
 3 |     let middle = &values[1..3];
 4 |     println!("{} {}", middle[0], middle[1]);
 5 | }
```

1. 원본 배열을 저장합니다
2. 인덱스 1과 2를 빌립니다
3. middle[0],middle[1]이 20,30입니다

`1..3` 부분이 실행될 때 읽는 값과 바뀌는 값을 한 줄씩 적어 보세요. 다음 `결과 예측과 작은 변경`에서는 이 부분이 달라집니다.

## 실행 추적

| 순서 | 상태 또는 동작 |
| ---: | -------------- |
|    1 | [10,20,30,40]  |
|    2 | [20,30] 빌림   |
|    3 | 20 30          |

위 순서대로 실행한 최종 출력은 `20 30`입니다. `[10,20,30,40]` 단계와 마지막 단계를 비교하면 입력과 출력의 관계가 보입니다.

## 다른 예제로 다시 이해하기

네 값 `[5,10,15,20]`에서 `[1..3]`은 인덱스 1과 2를 포함해 `[10,15]`입니다. 인덱스 3은 제외됩니다. `[1..4]`는 마지막 20까지 포함하고 `[4..4]`는 비어 있습니다. 끝 번호가 원소 개수와 같아도 **끝을 포함해 읽는 것은 아니므로** 유효할 수 있습니다.

## 결과 예측과 작은 변경

원본 실행 결과는 `20 30`입니다. 아래 코드에서 원본과 다른 줄을 먼저 찾으세요.

```rust
fn main() {
    let values = [11, 20, 30, 40];
    let middle = &values[1..3];
    println!("{} {}", middle[0], middle[1]);
}
```

찾은 줄을 적용했을 때의 실행 결과를 먼저 예측해 보세요.

해설: 바뀐 코드의 실행 결과는 아래와 같습니다.

```text
20 30
```

바꾼 뒤 출력도 `20 30`입니다. 슬라이스 1..3은 0번 원소를 포함하지 않아 결과가 같습니다. 바뀐 프로그램도 `[10,20,30,40]` 단계에서 시작해 `let values = [11, 20, 30, 40];` 줄을 지나 최종 `20 30`로 끝납니다. 원본 추적 `[10,20,30,40]  →  [20,30] 빌림  →  20 30`와 바뀐 줄 이후를 순서대로 놓으면 출력은 같아도 중간 값이 어디서 달라졌다가 합쳐지는지 확인할 수 있습니다.

## 자주 틀리는 지점

**확인할 실수: 끝 인덱스 3도 포함한다고 생각함.** 정상 코드의 실행 결과는 `20 30`입니다.

- 정상 줄: `let middle = &values[1..3];`
- 잘못된 줄: `let middle = &values[1..4];`

두 줄을 나란히 놓으면 정상 줄 `let middle = &values[1..3];`이 `슬라이스 [1..3]은 시작 1을 포함하고 끝 3은 제외하므로 원소 20,30을 빌립니다.` 설명과 맞고, 잘못된 줄은 `끝 인덱스 3도 포함한다고 생각함` 쪽으로 어긋납니다. 결과가 예상과 다르면 `[10,20,30,40]`부터 `20 30`까지 처음 어긋난 곳을 찾습니다.

## 다른 언어로 옮기기

세 언어에서 지켜야 할 핵심 동작은 `복사 없이 부분 범위를 빌림`입니다. 목표는 같은 입력에 같은 결과를 내는 것으로, 각 언어의 규칙에 맞게 옮겼는지 실행 결과로 대조하세요.

| 언어   | 옮길 때 확인할 표현과 규칙          |
| ------ | ----------------------------------- |
| C17    | 포인터 시작 위치와 길이를 함께 전달 |
| Python | values[1:3]은 새 리스트 생성        |
| Rust   | &values[1..3]은 빌림                |

C17에서는 `포인터 시작 위치와 길이를 함께 전달` 규칙을 적용합니다. "`Rust 슬라이스와 범위`" 수업의 실행 결과(`20 30`)를 기준으로 삼고, C는 범위와 널 검사를 자동으로 해 주지 않으므로, 코드에 사용된 접근마다 유효 범위를 직접 확인해야 합니다. Python에서는 `values[1:3]은 새 리스트 생성` 규칙을 따릅니다. 실패나 빈 입력은 예외로 드러내며 조용히 넘기지 마세요. Rust에서는 `&values[1..3]은 빌림` 규칙을 따릅니다. 실행 결과가 다르면 컴파일 오류(타입, 소유권, 빌림)와 실행 때 패닉(인덱스 범위 등) 중 어느 쪽인지 메시지부터 구분하세요.

## 실습 순서

예측(`20 30` 맞히기) → 빈칸(`1..3` 채우기) → 변경(`처음 등장하는 숫자를 10에서 11로`) → 오류 수정(`끝 인덱스 3도 포함한다고 생각함` 찾기) → 독립 구현(`'Rust 슬라이스와 범위' 개념을 보여주는 작은 프로그램` 만들기) 순으로 진행하세요. 각 단계의 답은 본문의 `20 30` 및 `1..3` 설명과 대조하세요.
