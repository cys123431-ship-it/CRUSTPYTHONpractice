## 오늘 배울 이유

배열 일부를 복사하지 않고 읽을 때 시작·끝 인덱스의 의미를 정확히 알아야 합니다. Day 36 "`Rust 슬라이스와 범위`"에서는 Rust 코드가 `20 30`을(를) 만드는 과정을 따라가며, 복사 없이 부분 범위를 빌림 동작이 왜 필요한지 확인합니다. 복사 없이 부분 범위를 빌림을(를) 빠뜨리면 `끝 인덱스 3도 포함한다고 생각함` 같은 문제가 생깁니다.

## 시작 전에 확인할 것

바로 앞선 [Day 35](/learn/day-35-ownership-review)에서는 "주소와 소유권 회상"을(를) 배웠습니다. "주소와 소유권 회상"의 핵심 결과를 한 문장으로 말해 보고, 이번 "`Rust 슬라이스와 범위`"에서 새로 달라지는 조건을 찾아보세요. Day 36의 답은 `20 30`이며, 핵심 표현은 `1..3`입니다.

## 머릿속 그림

슬라이스 [1..3]은 시작 1을 포함하고 끝 3은 제외하므로 원소 20,30을 빌립니다. Day 36에서는 아래 흐름 순서대로 상태가 바뀌며, `1..3`이(가) 결과를 가릅니다.

```text
[10,20,30,40]  →  [20,30] 빌림  →  20 30
```

위 흐름에서 `1..3`이(가) 실행되는 지점을 찾으면 읽는 값과 바뀌는 값이 나뉘어 보입니다. 마지막 출력은 `20 30`입니다.

## 천천히 풀어보기

슬라이스는 배열이나 Vec의 원소 일부를 **소유권 없이 잠시 보는 창**입니다. `[10,20,30,40]`에서 `[1..3]`은 1번을 포함하고 3번은 제외하므로 20과 30입니다. `[0..0]`은 아무 원소도 없는 빈 슬라이스입니다.

슬라이스의 끝은 길이까지 지정할 수 있습니다. 길이 4에서 `[1..4]`는 20,30,40이지만 `[1..5]`는 범위 밖입니다. 슬라이스를 빌려 쓰는 동안 원래 Vec를 재할당할 수 있는 `push` 같은 수정은 제한됩니다. 창이 바라보는 장소가 중간에 바뀌지 않게 하려는 규칙입니다.

## 문법을 예제로 보기

아래 Rust 코드는 Day 36 "`Rust 슬라이스와 범위`"의 독립 예제입니다. 전체 5줄에서 `1..3`이(가) 핵심이며, 실행 결과는 `20 30`입니다.

```rust
fn main() {
    let values = [10, 20, 30, 40];
    let middle = &values[1..3];
    println!("{} {}", middle[0], middle[1]);
}
```

예상 출력:

```text
20 30
```

Rust는 `rustc --edition=2024` 또는 Cargo로 실행하면 `20 30`이(가) 나옵니다. 브라우저에서는 임의 컴파일 대신 하단 실습 칸의 답안 비교를 사용하세요.

## 핵심 줄 따라 읽기

예제의 핵심 표현은 `1..3`입니다. 아래 줄 번호가 붙은 코드에서 이 표현이 있는 줄을 찾으세요.

```rust
 1 | fn main() {
 2 |     let values = [10, 20, 30, 40];
 3 |     let middle = &values[1..3];
 4 |     println!("{} {}", middle[0], middle[1]);
 5 | }
```

1. 원본 배열을 저장합니다
2. 인덱스 1과 2를 빌립니다
3. middle[0],middle[1]이 20,30입니다

위 단계에서 `1..3`이(가) 빠지면 `20 30`이(가) 나오지 않습니다. `처음 등장하는 숫자를 10에서 11로` 실험에서 어느 줄부터 달라지는지 직접 확인하세요.

## 실행 추적

| 순서 | 상태 또는 동작 |
| ---: | -------------- |
|    1 | [10,20,30,40]  |
|    2 | [20,30] 빌림   |
|    3 | 20 30          |

위 순서대로 실행하면 최종 출력 `20 30`이(가) 됩니다. `[10,20,30,40]` 단계와 마지막 단계를 비교하면 입력과 출력의 관계가 보입니다.

## 다른 예제로 다시 이해하기

네 값 `[5,10,15,20]`에서 `[1..3]`은 인덱스 1과 2를 포함해 `[10,15]`입니다. 인덱스 3은 제외됩니다. `[1..4]`는 마지막 20까지 포함하고 `[4..4]`는 비어 있습니다. 끝 번호가 원소 개수와 같아도 **끝을 포함해 읽는 것은 아니므로** 유효할 수 있습니다.

## 결과 예측과 작은 변경

원본 코드에서 `처음 등장하는 숫자를 10에서 11로` 바꾸면 아래와 같이 됩니다.

```rust
fn main() {
    let values = [11, 20, 30, 40];
    let middle = &values[1..3];
    println!("{} {}", middle[0], middle[1]);
}
```

원본 출력은 `20 30`입니다. 바꾼 코드를 실행하기 전에 출력이 어떻게 달라질지 먼저 적어 보세요. 출력이 같았다면 `1..3`이(가) 결과에 영향을 주지 않은 이유를, 달라졌다면 처음 달라진 중간 값을 설명하세요. Day 36의 `Rust 슬라이스와 범위`에서 바뀐 줄부터 다시 추적하세요.

## 자주 틀리는 지점

**확인할 실수: 끝 인덱스 3도 포함한다고 생각함.** 정상 코드에서는 `20 30`이(가) 출력됩니다.

- 정상 줄: `let middle = &values[1..3];`
- 잘못된 줄: `let middle = &values[1..4];`

두 줄을 나란히 놓고 `슬라이스 [1..3]은 시작 1을 포함하고 끝 3은 제외하므로 원소 20,30을 빌립니다.` 기준으로 어느 쪽이 맞는지 설명하세요. 결과가 예상과 다르면 `[10,20,30,40]`부터 `20 30`까지 처음 어긋난 곳을 찾습니다.

## 다른 언어로 옮기기

핵심 동작 **복사 없이 부분 범위를 빌림**은(는) 세 언어에서 같은 입력과 출력(`20 30`)으로 유지됩니다. 선언과 오류 처리는 언어마다 다릅니다.

| 언어   | 옮길 때 확인할 표현과 규칙          |
| ------ | ----------------------------------- |
| C17    | 포인터 시작 위치와 길이를 함께 전달 |
| Python | values[1:3]은 새 리스트 생성        |
| Rust   | &values[1..3]은 빌림                |
