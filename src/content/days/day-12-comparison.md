## 오늘 배울 이유

공부 시간 범위처럼 경계가 포함되는 조건은 연산자 하나로 오답이 갈립니다. Day 12 "`값 비교와 경계 포함`"에서는 Python 코드의 실행 결과(`True`)를 따라가며, `양쪽 경계를 포함해 비교함` 동작이 왜 필요한지 확인합니다. 이 동작이 빠지면 "`<= 대신 <를 써서 정확히 30 또는 60을 빠뜨림`" 같은 문제가 생깁니다.

## 시작 전에 확인할 것

바로 앞선 [Day 11](/learn/day-11-rust-types)에서 배운 "Rust 숫자 타입과 추론" 내용을 한 문장으로 말해 보세요. 이번 "`값 비교와 경계 포함`"에서 새로 달라지는 조건을 찾아보세요. 핵심 표현은 `<=`입니다.

## 머릿속 그림

30 <= minutes <= 60은 왼쪽·오른쪽 비교를 모두 만족해야 참입니다. Day 12에서는 아래 흐름 순서대로 상태가 바뀌고, 결과를 가르는 부분은 `<=`입니다.

```text
30<=45 참  →  45<=60 참  →  True
```

위 흐름에서 `<=` 부분이 실행되는 지점을 찾으면 읽는 값과 바뀌는 값이 나뉘어 보입니다. 마지막 출력은 `True`입니다.

## 천천히 풀어보기

`30 <= minutes <= 60`은 `minutes`가 30 이상이고 동시에 60 이하인지 검사합니다. 30과 60도 포함됩니다. 29는 왼쪽 조건이 거짓이고 61은 오른쪽 조건이 거짓입니다. 29, 30, 60, 61 네 값을 넣어 표를 만들어 보세요.

Python에서 이처럼 이어 쓴 비교는 중간 값에 대해 양쪽 조건을 확인합니다. C나 Rust의 같은 문법으로 옮기지 말고 각각 `minutes >= 30 && minutes <= 60` 같은 논리곱으로 적어야 합니다. 경계에서 무엇을 포함할지 문제 문장부터 확정하세요.

## 문법을 예제로 보기

아래 Python 코드는 Day 12 "`값 비교와 경계 포함`"의 독립 예제입니다. 전체 2줄 가운데 핵심 부분은 `<=`이며, 실행 결과는 `True`입니다.

```python
minutes = 45
print(30 <= minutes <= 60)
```

예상 출력:

```text
True
```

하단 Python 실행 영역에 같은 코드가 들어 있습니다. 먼저 실행 결과(`True`)를 가리고 예측한 뒤 실행해 비교하세요.

## 핵심 줄 따라 읽기

예제의 핵심 표현은 `<=`입니다. 아래 줄 번호가 붙은 코드에서 이 표현이 있는 줄을 찾으세요.

```python
 1 | minutes = 45
 2 | print(30 <= minutes <= 60)
```

1. 30 <= 45가 참입니다
2. 45 <= 60도 참입니다
3. 두 조건을 연결해 True입니다

`<=` 부분이 실행될 때 읽는 값과 바뀌는 값을 한 줄씩 적어 보세요. 다음 `결과 예측과 작은 변경`에서는 이 부분이 달라집니다.

## 실행 추적

| 순서 | 상태 또는 동작 |
| ---: | -------------- |
|    1 | 30<=45 참      |
|    2 | 45<=60 참      |
|    3 | True           |

위 순서대로 실행한 최종 출력은 `True`입니다. `30<=45 참` 단계와 마지막 단계를 비교하면 입력과 출력의 관계가 보입니다.

## 다른 예제로 다시 이해하기

`minutes = 60`이면 `30 <= minutes <= 60`의 두 비교는 모두 참입니다. 61로 바꾸면 앞쪽은 참, 뒤쪽은 거짓이라 전체는 거짓입니다. 경계 30과 60은 포함되고 29와 61은 빠진다는 사실을 **각각의 비교 결과**로 설명해 보세요. C/Rust로 옮길 때 비교식을 그대로 이어 쓰지 않습니다.

## 결과 예측과 작은 변경

원본 실행 결과는 `True`입니다. 아래 코드에서 원본과 다른 줄을 먼저 찾으세요.

```python
minutes = 46
print(30 <= minutes <= 60)
```

찾은 줄을 적용했을 때의 실행 결과를 먼저 예측해 보세요.

해설: 바뀐 코드의 실행 결과는 아래와 같습니다.

```text
True
```

`True`로 같습니다. 46도 30 이상 60 이하 구간 안에 있어 비교 결과가 그대로 True입니다. 출력이 같다고 해서 중간 상태까지 같은 것은 아닙니다. 다른 줄(`minutes = 46`)부터 원본 추적과 비교해 보세요.

## 자주 틀리는 지점

**확인할 실수: <= 대신 <를 써서 정확히 30 또는 60을 빠뜨림.** 정상 코드의 실행 결과는 `True`입니다.

- 정상 줄: `print(30 <= minutes <= 60)`
- 잘못된 줄: `print(30 < minutes <= 60)`

두 줄을 나란히 놓고 `30 <= minutes <= 60은 왼쪽·오른쪽 비교를 모두 만족해야 참입니다.` 기준으로 어느 쪽이 맞는지 설명하세요. 결과가 예상과 다르면 `30<=45 참`부터 `True`까지 처음 어긋난 곳을 찾습니다.

## 다른 언어로 옮기기

세 언어에서 지켜야 할 핵심 동작은 `양쪽 경계를 포함해 비교함`입니다. 목표는 같은 입력에 같은 결과를 내는 것으로, 각 언어의 규칙에 맞게 옮겼는지 실행 결과로 대조하세요.

| 언어   | 옮길 때 확인할 표현과 규칙     |
| ------ | ------------------------------ |
| C17    | 30 <= minutes && minutes <= 60 |
| Python | 30 <= minutes <= 60            |
| Rust   | 30 <= minutes && minutes <= 60 |

C17에서는 `30 <= minutes && minutes <= 60` 규칙을 적용합니다. "`값 비교와 경계 포함`" 수업의 실행 결과(`True`)를 기준으로 삼고, C는 범위와 널 검사를 자동으로 해 주지 않으므로, 코드에 사용된 접근마다 유효 범위를 직접 확인해야 합니다. Python에서는 `30 <= minutes <= 60` 규칙을 따릅니다. 실패나 빈 입력은 예외로 드러내며 조용히 넘기지 마세요. Rust에서는 `30 <= minutes && minutes <= 60` 규칙을 따릅니다. 실행 결과가 다르면 컴파일 오류(타입, 소유권, 빌림)와 실행 때 패닉(인덱스 범위 등) 중 어느 쪽인지 메시지부터 구분하세요.

## 실습 순서

예측(`True` 맞히기) → 빈칸(`<=` 채우기) → 변경(`처음 등장하는 숫자를 45에서 46로`) → 오류 수정(`<= 대신 <를 써서 정확히 30 또는 60을 빠뜨림` 찾기) → 독립 구현(`값 비교와 경계 포함을 보여 주는` 만들기) 순으로 진행하세요. 각 단계의 답은 본문의 `True` 및 `<=` 설명과 대조하세요.
