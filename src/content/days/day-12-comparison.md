## 1. 오늘 배울 내용

Day 8에서 비교의 결과가 불리언이라는 것을 봤습니다. 오늘은 **무엇을 어떻게 비교하는지**와 조건의 **경계**를 정확히 다룹니다. 다음 날 배울 조건문의 정확성은 여기서 결정됩니다.

1. 여섯 가지 비교 연산자 `==`, `!=`, `<`, `<=`, `>`, `>=`와, 서로 다른 자료형을 비교할 때의 규칙.
2. **문자열 비교**: 글자 번호로 앞에서부터 비교하는 사전식 순서.
   - C는 `strcmp`를 씁니다.
   - Rust는 `cmp`와 `Ordering`을 씁니다.
3. Python의 `==`(값이 같은가)와 `is`(같은 대상인가).
4. **구간**을 두 가지로 표현합니다.
   - 닫힌 구간 `[a, b]`: `a..=b`
   - 반열린 구간 `[a, b)`: `a..b`
5. **off-by-one 오류**(울타리 기둥 문제)와 **경계값 시험**을 익힙니다.

## 2. 왜 필요한가

조건문 버그의 상당수는 "90점은 A인가 B인가", "마감 시각 18:00 정각은 늦은 것인가"처럼 **경계에서** 생깁니다. `>`와 `>=` 하나 차이로 90점 학생이 B를 받는 프로그램이 됩니다. 이런 버그는 경계값을 넣어 보지 않으면 드러나지 않습니다.

문자열 비교도 직관과 다릅니다. 파일 이름을 정렬했더니 `file10.txt`가 `file9.txt`보다 앞에 오고, 버전 `1.10`이 `1.9`보다 "작다"고 나옵니다. 컴퓨터가 문자열을 **글자 번호**로 비교하기 때문입니다. 규칙을 알아야 이런 결과를 이해하고 고칠 수 있습니다.

## 3. 그림으로 이해하기

**구간**은 수직선 위의 범위입니다. 끝점을 포함하면 속이 찬 점(●), 포함하지 않으면 빈 점(○)으로 그립니다.

```text
닫힌 구간 [80, 90]       80 ≤ x ≤ 90
   ──────●━━━━━━━━━━━━━━━━━━━━●──────
        80                    90

반열린 구간 [80, 90)     80 ≤ x < 90
   ──────●━━━━━━━━━━━━━━━━━━━━○──────
        80                    90

반열린 구간은 빈틈없이 이어 붙일 수 있다
   ●━━━━━━━━━○●━━━━━━━━━○●━━━━━━━━━○
   70   [70,80)  80  [80,90)  90  [90,100)
   (90점은 정확히 한 구간에만 속한다)
```

**문자열 비교**는 사전에서 단어를 찾는 방식입니다. 첫 글자부터 비교하고, 같으면 다음 글자로 넘어갑니다.

```text
"apple" vs "apricot"          "10" vs "9"
 a = a                         '1'(49) < '9'(57)  → "10"이 앞!
 p = p
 p(112) < r(114) → "apple"이 앞

"cat" vs "catalog"
 c = c, a = a, t = t, 앞 문자열이 먼저 끝남 → 짧은 쪽 "cat"이 앞
```

## 4. 천천히 풀어보기

### 4.1 비교 연산자

| 연산자 | 뜻          | `90`과 `90` | `89`와 `90` |
| ------ | ----------- | ----------- | ----------- |
| `==`   | 같다        | 참          | 거짓        |
| `!=`   | 다르다      | 거짓        | 참          |
| `<`    | 작다        | 거짓        | 참          |
| `<=`   | 작거나 같다 | 참          | 참          |
| `>`    | 크다        | 거짓        | 거짓        |
| `>=`   | 크거나 같다 | 참          | 거짓        |

"이상·이하"는 경계를 포함(`>=`, `<=`), "초과·미만"은 포함하지 않습니다(`>`, `<`).

### 4.2 서로 다른 자료형 비교

| 비교              | Python                       | C                             | Rust                     |
| ----------------- | ---------------------------- | ----------------------------- | ------------------------ |
| 정수 vs 실수      | 가능(`90 == 90.0` 참)        | 가능(정수가 double로 바뀜)    | 불가능, `as`로 맞춰야 함 |
| 부호 있음 vs 없음 | (해당 없음)                  | 가능하지만 위험(Day 6, 경고)  | 불가능                   |
| 숫자 vs 문자열    | `==`는 거짓, `<`는 TypeError | (문자열은 주소라 비교 무의미) | 불가능                   |
| 불리언 vs 정수    | 가능(`True == 1` 참)         | 가능(`true`는 1)              | 불가능                   |

Rust는 비교할 두 값의 자료형이 **정확히 같아야** 합니다. 대신 `String`과 `&str`처럼 "같은 뜻의 문자열"끼리는 `==`로 비교할 수 있게 만들어져 있습니다.

### 4.3 문자열과 묶음의 비교

문자열은 **글자 번호**(ASCII, 유니코드)로 비교합니다. 알아 둘 번호 순서는 다음과 같습니다.

```text
공백(32) < 숫자 '0'~'9'(48~57) < 대문자 'A'~'Z'(65~90) < 소문자 'a'~'z'(97~122) < 한글 '가'(44032)~
```

그래서 대문자는 모두 소문자보다 앞이고, 한글은 영문보다 뒤입니다. 한글끼리는 유니코드가 가나다순으로 배치되어 있어 `"가" < "나"`가 참입니다.

- **C**: 문자열 변수는 글자들이 있는 **위치(주소)** 라서 `==`로 내용을 비교할 수 없습니다. `strcmp(s, t)`가 같으면 0, `s`가 앞이면 음수, 뒤면 양수를 돌려줍니다.
- **Python, Rust**: 문자열의 `==`, `<`가 내용을 비교합니다.

튜플(값 묶음)과 리스트도 **앞에서부터** 하나씩 비교합니다. `(1, 10, 0) > (1, 9, 5)`는 첫 값이 같고 둘째 값 10 > 9에서 참으로 끝납니다.

### 4.4 ==와 is (Python)

`==`는 **값**이 같은지, `is`는 **같은 대상**(메모리의 같은 객체)인지 묻습니다. 내용이 같은 리스트를 두 번 만들면 `==`는 참, `is`는 거짓입니다. `is`는 `x is None`처럼 "특별한 값 하나"를 확인할 때만 쓰세요. 숫자나 문자열을 `is`로 비교하면 우연히 맞았다 틀렸다 합니다.

### 4.5 구간과 개수

| 표현        | 수학     | Python 조건   | Rust 범위 | C 조건             | 정수 개수   |
| ----------- | -------- | ------------- | --------- | ------------------ | ----------- |
| 닫힌 구간   | `[a, b]` | `a <= x <= b` | `a..=b`   | `a <= x && x <= b` | `b - a + 1` |
| 반열린 구간 | `[a, b)` | `a <= x < b`  | `a..b`    | `a <= x && x < b`  | `b - a`     |

반열린 구간은 **개수가 `b - a`로 깔끔하고**, 이어 붙일 때 겹치거나 빠지는 값이 없어서 프로그래밍에서 기본으로 씁니다. 배열의 인덱스 0부터 길이 n까지를 `[0, n)`으로 나타내는 것도 같은 이유입니다(Day 26). Python의 `range(0, 10)`과 Rust의 `0..10`은 모두 10을 포함하지 않습니다.

## 5. C로 구현하기

```c
// 파일: compare.c
#include <stdio.h>
#include <string.h>                     // strcmp

int main(void) {
    int a = 90;
    double b = 89.5;
    printf("%d %d %d %d %d\n", a > b, a == 90.0, a != b, a >= 90, a < 90);

    printf("'A' < 'a': %d ('A' = %d, 'a' = %d)\n", 'A' < 'a', 'A', 'a');
    printf("strcmp(\"apple\", \"banana\") < 0: %d\n", strcmp("apple", "banana") < 0);
    printf("strcmp(\"10\", \"9\") < 0: %d\n", strcmp("10", "9") < 0);
    printf("strcmp(\"cat\", \"cat\") == 0: %d\n", strcmp("cat", "cat") == 0);

    int x = 90;
    printf("[80, 90)에 있나: %d, [90, 100)에 있나: %d\n",
           80 <= x && x < 90, 90 <= x && x < 100);

    int bigger = a > 85 ? a : 85;       // 둘 중 큰 값
    printf("max(90, 85) = %d\n", bigger);
    printf("-1 < 0: %d, 'Z' < 'a': %d\n", -1 < 0, 'Z' < 'a');
    return 0;
}
```

strcmp("apple", "banana") < 0: 1
strcmp("10", "9") < 0: 1
strcmp("cat", "cat") == 0: 1
[80, 90)에 있나: 0, [90, 100)에 있나: 1
max(90, 85) = 90
-1 < 0: 1, 'Z' < 'a': 1

## 7. Rust로 구현하기

Rust는 비교 연산자 외에 **`cmp`** 메서드로 "작다·같다·크다" 세 결과를 한 번에 얻을 수 있습니다. 결과는 `Ordering`이라는 **enum**(Day 53)으로, `Less`, `Equal`, `Greater` 중 하나입니다.

```rust
// 파일: compare.rs
use std::cmp::Ordering;

fn main() {
    let a = 90;
    let b = 89.5;
    println!("{} {}", a as f64 > b, a == 90);          // 같은 자료형끼리만 비교

    println!("{} {} {}", "apple" < "banana", "Apple" < "apple", "10" < "9");
    println!("{:?} {:?} {:?}", 3_i32.cmp(&7), 7_i32.cmp(&3), 5_i32.cmp(&5));

    let name = String::from("cat");
    println!("String == &str: {}", name == "cat");
    println!("{} {}", 3_i32.max(7), "pear".min("apple"));

    let x = 90;
    println!("{} {} {}", (80..90).contains(&x), (90..100).contains(&x), (80..=90).contains(&x));
    println!("{} {}", (1, 2) < (1, 3), [1, 2] == [1, 2]);

    match 85_i32.cmp(&90) {
        Ordering::Less => println!("85는 90보다 작다"),
        Ordering::Equal => println!("같다"),
        Ordering::Greater => println!("크다"),
    }
    println!("0.5와 NaN 비교: {:?}", 0.5_f64.partial_cmp(&f64::NAN));
}
```

실행 결과:

```text
true true
true true true
Less Greater Equal
String == &str: true
7 apple
false true true
true true
85는 90보다 작다
0.5와 NaN 비교: None
```

### 코드 한 부분씩 읽기

| 코드                                      | 설명                                                                                                                                                       |
| ----------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `a as f64 > b`                            | 정수와 실수는 바로 비교할 수 없어 자료형을 맞춥니다.                                                                                                       |
| `3_i32.cmp(&7)`                           | 결과는 `Ordering::Less`입니다. `&7`은 "7을 빌려준다"는 뜻으로, 비교하는 동안 값을 가져가지 않습니다(Day 33). 숫자 뒤의 `_i32`는 어떤 정수인지 알려 줍니다. |
| `name == "cat"`                           | `String`과 `&str`은 다른 자료형이지만 문자열끼리라 비교할 수 있습니다.                                                                                     |
| `"pear".min("apple")`                     | 크기 비교가 가능한 자료형은 `max`, `min` 메서드를 가집니다.                                                                                                |
| `(80..90).contains(&x)`                   | 반열린 범위 `80..90`은 90을 포함하지 않아 거짓, `80..=90`은 포함해서 참입니다.                                                                             |
| `match 85_i32.cmp(&90) { ... }`           | `Ordering`의 세 경우를 나눠 처리합니다. `match`는 Day 15에서 자세히 배우니, 지금은 "결과에 맞는 줄 하나가 실행된다"고 읽으면 됩니다.                       |
| `0.5_f64.partial_cmp(&f64::NAN)` → `None` | 실수는 NaN 때문에 **항상** 크기를 비교할 수 있지는 않습니다. 그래서 실수에는 `cmp` 대신 결과가 없을 수도 있는 `partial_cmp`가 있습니다(Day 11).            |

## 8. 실행 추적

`"apple" < "apricot"`과 `"cat" < "catalog"`을 글자 단위로 비교하는 과정입니다.

| 위치 | `"apple"` | `"apricot"` | 비교      | 결정?                 |
| ---: | --------- | ----------- | --------- | --------------------- |
|    0 | `a` (97)  | `a` (97)    | 같음      | 다음 글자로           |
|    1 | `p` (112) | `p` (112)   | 같음      | 다음 글자로           |
|    2 | `p` (112) | `r` (114)   | 112 < 114 | **"apple"이 앞** → 참 |

| 위치 | `"cat"` | `"catalog"` | 비교                  | 결정?               |
| ---: | ------- | ----------- | --------------------- | ------------------- |
|  0~2 | `c a t` | `c a t`     | 모두 같음             | 다음 글자로         |
|    3 | (끝)    | `a`         | 앞 문자열이 먼저 끝남 | **"cat"이 앞** → 참 |

한쪽이 먼저 끝나면 **짧은 쪽이 앞**입니다. 사전에서 "cat"이 "catalog"보다 앞에 나오는 것과 같습니다.

## 9. 다른 예제로 다시 이해하기

**경계값 시험.** 성적 구간 [80, 90)을 닫힌 구간으로 잘못 쓰면 어떤 점수에서 드러날까요? 경계와 그 양옆의 값(79, 80, 89, 90, 91)을 모두 넣어 봅시다.

```python
# 파일: boundaries.py
lo, hi = 80, 90
print("점수  [80, 90]  [80, 90)")
for score in (79, 80, 89, 90, 91):
    closed = lo <= score <= hi
    half_open = lo <= score < hi
    print(f"{score:>4}  {closed!s:<8}  {half_open}")

print("80~90 정수 개수:", hi - lo + 1, "(닫힌)", hi - lo, "(반열린)")

length, gap = 100, 10
print("100m 길에 10m마다 기둥:", length // gap + 1, "개, 칸:", length // gap, "개")
```

실행 결과:

```text
점수  [80, 90]  [80, 90)
  79  False     False
  80  True      True
  89  True      True
  90  True      False
  91  False     False
80~90 정수 개수: 11 (닫힌) 10 (반열린)
100m 길에 10m마다 기둥: 11 개, 칸: 10 개
```

두 조건은 **90에서만** 결과가 다릅니다. 50점이나 85점만 시험했다면 차이를 발견하지 못했을 것입니다. 조건을 만들면 **경계값, 경계 바로 아래, 경계 바로 위**를 반드시 넣어 보세요.

마지막 두 줄은 **울타리 기둥 문제(fencepost problem)** 입니다. 100m를 10m씩 나누면 칸은 10개지만, 양 끝을 포함한 기둥은 11개입니다. "끝점을 세는가, 사이를 세는가"를 헷갈리면 답이 1 어긋납니다.

Rust로 나이대를 반열린 범위로 나눠 봅시다. 범위를 **빈틈없이 이어 붙이면** 모든 나이가 정확히 한 구간에 들어갑니다.

```rust
// 파일: age_group.rs
fn main() {
    for age in [0, 12, 13, 19, 20, 64, 65] {
        let child = (0..13).contains(&age);
        let teen = (13..20).contains(&age);
        let adult = (20..65).contains(&age);
        let senior = (65..).contains(&age);
        println!("{age:>2}세: 어린이 {child:<5} 청소년 {teen:<5} 성인 {adult:<5} 노인 {senior}");
    }
}
```

실행 결과:

```text
 0세: 어린이 true  청소년 false 성인 false 노인 false
12세: 어린이 true  청소년 false 성인 false 노인 false
13세: 어린이 false 청소년 true  성인 false 노인 false
19세: 어린이 false 청소년 true  성인 false 노인 false
20세: 어린이 false 청소년 false 성인 true  노인 false
64세: 어린이 false 청소년 false 성인 true  노인 false
65세: 어린이 false 청소년 false 성인 false 노인 true
```

어느 줄에도 `true`가 정확히 하나씩입니다. `65..`는 "65 이상 전부"라는 끝없는 범위입니다. 경계인 13, 20, 65와 그 바로 앞 값(12, 19, 64)을 넣어 겹침이나 빈틈이 없는지 확인했습니다.

`i64::from(count) < limit`처럼 한쪽으로 맞춥니다.

### 실수 4: >와 >=를 헷갈린다

"90점 이상 A"를 `score > 90`으로 쓰면 90점이 A를 받지 못합니다. 문제의 "이상/이하/초과/미만"을 연산자로 옮긴 뒤, **경계값으로 시험**하세요.

### 실수 5: 개수를 셀 때 1이 어긋난다

"3일부터 7일까지 휴가"는 7 − 3 = 4일이 아니라 **5일**입니다(3, 4, 5, 6, 7). 양 끝을 포함하면 `+ 1`, 반열린 구간이면 그대로입니다.

## 13. Q&A

**Q. 한글 문자열 정렬은 가나다순으로 되나요?**

A. 한글 음절만 있으면 유니코드 번호가 가나다순이라 대체로 맞습니다. 하지만 자모(ㄱ, ㅏ)가 섞이거나, 영문과 섞이면 사람이 기대하는 순서와 다를 수 있습니다. 실제 서비스에서는 언어별 정렬 규칙(로캘, collation)을 적용하는 라이브러리를 씁니다.

**Q. 파일 이름을 "사람처럼" 정렬하려면요?**

A. `file9`와 `file10`을 숫자 부분은 숫자로 비교하는 방식을 **자연 정렬(natural sort)** 이라고 합니다. 문자열을 숫자 부분과 글자 부분으로 나눠 튜플로 만든 뒤 비교하면 됩니다. 정렬은 Day 73~77에서 자세히 배웁니다.

**Q. Rust의 `cmp`는 왜 `&`를 붙여서 넘기나요?**

A. `cmp`는 비교할 값을 **빌려서** 봅니다. 숫자는 복사가 싸서 차이가 없지만, 긴 문자열이나 큰 구조체를 비교할 때 값을 통째로 넘기면 비효율적이고 원래 변수를 쓸 수 없게 될 수도 있기 때문입니다. 빌림은 Day 33에서 배웁니다.

**Q. `a <= x <= b`가 Python에서만 되는 이유는요?**

A. Python은 `a <= x <= b`를 `a <= x and x <= b`로 **바꿔 해석**하도록 설계했습니다. C는 왼쪽부터 `(a <= x) <= b`로 계산해 0 또는 1과 b를 비교하고, Rust는 이런 모호함을 막으려고 문법 오류로 만들었습니다.

## 14. 핵심 요약

- 비교 연산자는 `== != < <= > >=`입니다. "이상·이하"는 경계 포함(`>=`, `<=`), "초과·미만"은 제외(`>`, `<`)입니다.
- Python은 숫자끼리 자료형이 달라도 비교하고, C는 자동 변환 후 비교하고, Rust는 같은 자료형만 비교합니다.
- 문자열은 **글자 번호로 앞에서부터** 비교합니다(숫자 < 대문자 < 소문자 < 한글, `"10" < "9"`). 튜플도 앞에서부터 비교합니다.
- C의 문자열은 `strcmp`로 비교합니다(같으면 0). Python과 Rust의 `==`는 내용을 비교합니다. Python의 `is`는 같은 대상인지 묻습니다.
- 닫힌 구간 `[a, b]`는 `a..=b`, 개수 `b - a + 1`. 반열린 구간 `[a, b)`는 `a..b`, 개수 `b - a`. 반열린 구간이 기본입니다.
- 조건은 **경계값과 그 양옆**으로 시험합니다.
