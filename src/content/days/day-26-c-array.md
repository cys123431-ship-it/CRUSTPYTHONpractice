## 오늘 배울 이유

여러 값을 순서대로 저장하려면 연속된 메모리의 배열과 유효 인덱스를 알아야 합니다. Day 26 "`C 배열과 인덱스`"에서는 C 코드의 실행 결과(`20`)를 따라가며, `배열 위치로 값 조회` 동작이 왜 필요한지 확인합니다. 이 동작이 빠지면 "`길이 3의 마지막 인덱스를 3으로 착각해 범위 밖을 읽음`" 같은 문제가 생깁니다.

## 시작 전에 확인할 것

바로 앞선 [Day 25](/learn/day-25-result-error)에서 배운 "Rust Result와 실패 전달" 내용을 한 문장으로 말해 보세요. 이번 "`C 배열과 인덱스`"에서 새로 달라지는 조건을 찾아보세요. 핵심 표현은 `[1]`입니다.

## 머릿속 그림

길이 3 배열의 첫 원소는 0번이고 마지막은 2번입니다. 1번은 두 번째 값입니다. Day 26에서는 아래 흐름 순서대로 상태가 바뀌고, 결과를 가르는 부분은 `[1]`입니다.

```text
인덱스 0=10  →  인덱스 1=20  →  출력
```

위 흐름에서 `[1]` 부분이 실행되는 지점을 찾으면 읽는 값과 바뀌는 값이 나뉘어 보입니다. 마지막 출력은 `20`입니다.

## 천천히 풀어보기

배열 `a = {10,20,30}`은 같은 타입의 세 값을 순서대로 붙여 저장합니다. 번호는 0부터 시작하므로 `a[0]=10`, `a[1]=20`, `a[2]=30`입니다. '두 번째'라는 일상 말과 인덱스 1의 차이를 구별하세요.

`a[3]`은 길이 3의 범위 밖입니다. C는 이런 읽기를 자동으로 안전하게 막아주지 않으므로 이상한 값이 보이거나 프로그램이 망가질 수 있습니다. 반복문이라면 `i < 3`을 종료 조건으로 정하고, `i <= 3`과 무엇이 다른지 네 값을 넣어 확인하세요.

## 문법을 예제로 보기

아래 C 코드는 Day 26 "`C 배열과 인덱스`"의 독립 예제입니다. 전체 6줄 가운데 핵심 부분은 `[1]`이며, 실행 결과는 `20`입니다.

```c
#include <stdio.h>
int main(void) {
    int minutes[3] = {10, 20, 30};
    printf("%d\n", minutes[1]);
    return 0;
}
```

예상 출력:

```text
20
```

C17은 `gcc -std=c17 -Wall -Wextra`로 컴파일해 실행하면 실행 결과는 `20`입니다. 브라우저에서는 임의 컴파일 대신 하단 실습 칸의 답안 비교를 사용하세요.

## 핵심 줄 따라 읽기

예제의 핵심 표현은 `[1]`입니다. 아래 줄 번호가 붙은 코드에서 이 표현이 있는 줄을 찾으세요.

```c
 1 | #include <stdio.h>
 2 | int main(void) {
 3 |     int minutes[3] = {10, 20, 30};
 4 |     printf("%d\n", minutes[1]);
 5 |     return 0;
 6 | }
```

1. 배열에 10·20·30을 순서대로 저장합니다
2. 인덱스 1을 읽어 20을 얻습니다
3. printf가 출력합니다

`[1]` 부분이 실행될 때 읽는 값과 바뀌는 값을 한 줄씩 적어 보세요. 다음 `결과 예측과 작은 변경`에서는 이 부분이 달라집니다.

## 실행 추적

| 순서 | 상태 또는 동작 |
| ---: | -------------- |
|    1 | 인덱스 0=10    |
|    2 | 인덱스 1=20    |
|    3 | 출력           |

위 순서대로 실행한 최종 출력은 `20`입니다. `인덱스 0=10` 단계와 마지막 단계를 비교하면 입력과 출력의 관계가 보입니다.

## 다른 예제로 다시 이해하기

**세 칸을 실제로 그려 보세요.** `int minutes[3] = {10,20,30};`을 실행하면 다음과 같이 채워집니다. 번호는 0부터 시작하지만, 칸의 개수는 3입니다.

| 인덱스    |   0 |   1 |   2 |
| --------- | --: | --: | --: |
| 저장된 분 |  10 |  20 |  30 |

`minutes[1]`을 읽으면 가운데 칸 20입니다. 괄호 속 숫자 1을 2로 바꿔 `minutes[2]`을 읽으면 마지막 칸 30이 나옵니다. 출력이 달라진 까닭은 배열을 바꿔서가 아니라 **읽는 칸을 바꿨기 때문**입니다. `minutes[3]`은 네 번째 칸인데 실제 칸이 세 개라서 읽으면 안 됩니다.

이번에는 배열 값을 모두 더해 보세요. `total`은 처음에 0이고, 반복할 때마다 값 하나가 더해집니다.

```c
#include <stdio.h>
int main(void) {
    int minutes[3] = {10, 20, 30};
    int total = 0;
    for (int i = 0; i < 3; i++) {
        total += minutes[i];
    }
    printf("%d\n", total);  // 60
    return 0;
}
```

반복 시작 때 `i=0, total=0`, 첫 번 뒤 10, 둘째 번 뒤 30, 셋째 번 뒤 60입니다. 그다음 `i=3`이면 `i < 3`이 거짓이라 본문에 들어가지 않습니다. `i <= 3`으로 쓰면 마지막에 없는 `minutes[3]`을 읽는 위험이 생깁니다. C의 배열은 이런 실수를 실행 전에 자동으로 해결해 주지 않으므로 조건을 직접 맞춰야 합니다.

**같은 작업을 다른 언어로:** Python에서는 `minutes = [10,20,30]; print(minutes[2])`가 30입니다. Rust에서는 `let minutes = [10,20,30]; println!("{}", minutes[2]);`가 30입니다. 두 언어 모두 범위를 넘는 접근을 오류로 드러내지만 C에서는 그 결과를 믿을 수 없습니다. 지금 단계에서는 세 언어의 문법보다 **세 칸의 번호가 0·1·2라는 공통점**을 먼저 잡으세요.

## 결과 예측과 작은 변경

원본 실행 결과는 `20`입니다. 아래 코드에서 원본과 다른 줄을 먼저 찾으세요.

```c
#include <stdio.h>
int main(void) {
    int minutes[3] = {10, 20, 30};
    printf("%d\n", minutes[2]);
    return 0;
}
```

찾은 줄을 적용했을 때의 실행 결과를 먼저 예측해 보세요.

해설: 바뀐 코드의 실행 결과는 아래와 같습니다.

```text
30
```

원본과 달라졌습니다. 원본 출력은 `20`입니다. 다른 줄(`printf("%d\n", minutes[1]);` → `printf("%d\n", minutes[2]);`)에서 시작된 차이가 이후 흐름을 타고 최종 출력에 반영되었습니다. 원본 추적(`인덱스 0=10` → …)과 바뀐 줄부터 대조해 보세요.

## 자주 틀리는 지점

**확인할 실수: 길이 3의 마지막 인덱스를 3으로 착각해 범위 밖을 읽음.** 정상 코드의 실행 결과는 `20`입니다.

- 정상 줄: `printf("%d\n", minutes[1]);`
- 잘못된 줄: `printf("%d\n", minutes[3]);`

두 줄을 나란히 놓고 `길이 3 배열의 첫 원소는 0번이고 마지막은 2번입니다. 1번은 두 번째 값입니다.` 기준으로 어느 쪽이 맞는지 설명하세요. 결과가 예상과 다르면 `인덱스 0=10`부터 `20`까지 처음 어긋난 곳을 찾습니다.

## 다른 언어로 옮기기

세 언어에서 지켜야 할 핵심 동작은 `배열 위치로 값 조회`입니다. 목표는 같은 입력에 같은 결과를 내는 것으로, 각 언어의 규칙에 맞게 옮겼는지 실행 결과로 대조하세요.

| 언어   | 옮길 때 확인할 표현과 규칙        |
| ------ | --------------------------------- |
| C17    | int a[3]와 a[1]                   |
| Python | list의 a[1], 범위 밖은 IndexError |
| Rust   | [i32;3]의 a[1], 범위 밖 검사      |

C17에서는 `int a[3]와 a[1]` 규칙을 적용합니다. "`C 배열과 인덱스`" 수업의 실행 결과(`20`)를 기준으로 삼고, C는 범위와 널 검사를 자동으로 해 주지 않으므로, 코드에 사용된 접근마다 유효 범위를 직접 확인해야 합니다. Python에서는 `list의 a[1], 범위 밖은 IndexError` 규칙을 따릅니다. 실패나 빈 입력은 예외로 드러내며 조용히 넘기지 마세요. Rust에서는 `[i32;3]의 a[1], 범위 밖 검사` 규칙을 따릅니다. 실행 결과가 다르면 컴파일 오류(타입, 소유권, 빌림)와 실행 때 패닉(인덱스 범위 등) 중 어느 쪽인지 메시지부터 구분하세요.

## 실습 순서
