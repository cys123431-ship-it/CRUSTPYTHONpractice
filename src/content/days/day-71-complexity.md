    starter: |-
      fn main() {

          }
      }
    answer: |-
      fn max_comparisons(a: &[i32]) -> (i32, usize) {
          let mut best = a[0];
          let mut count = 0;
          for &x in &a[1..] {
              count += 1;
              if x > best {
                  best = x;
              }
          }
          (best, count)
      }

      fn selection_comparisons(a: &mut [i32]) -> usize {
          let mut count = 0;
          for i in 0..a.len() {
              let mut min_i = i;
              for j in i + 1..a.len() {
                  count += 1;
                  if a[j] < a[min_i] {
                      min_i = j;
                  }
              }
              a.swap(i, min_i);
          }
          count
      }

      fn main() {
          for n in [5usize, 10, 100] {
              let mut data: Vec<i32> = (0..n as i32).rev().collect();
              let (_, max_count) = max_comparisons(&data);
              let sort_count = selection_comparisons(&mut data);
              println!("{max_count} {sort_count}");
          }
      }
    output: |-

      9 45
      99 4950

## 1. 오늘 배울 내용

Phase 7에서는 **알고리즘**을 배웁니다. 알고리즘은 문제를 푸는 **절차**입니다. 같은 문제를 푸는 알고리즘은 여러 가지가 있고, 입력이 커지면 그 차이가 **몇 초와 몇 년**만큼 벌어지기도 합니다. 오늘은 알고리즘의 빠르기를 재는 **공통 언어인 시간 복잡도**를 배웁니다.

1. 왜 실행 시간이 아니라 **연산 횟수**로 비교하는지 알아봅니다.
2. 여러 반복문의 연산 횟수를 **직접 세어 보고** 빅오(Big-O)로 나타냅니다.
3. O(1), O(log n), O(n), O(n log n), O(n²), O(2ⁿ)이 얼마나 빨리 자라는지 **C, Python, Rust** 프로그램으로 확인합니다.
4. 빅오를 읽는 규칙과 **최악·평균**, **공간 복잡도**를 배웁니다.
5. **입력 크기**로 필요한 알고리즘을 가늠하는 법과, 큰 수를 셀 때의 **정수 넘침**을 다룹니다.
6. 응용으로 피보나치 수를 재귀로 구할 때 왜 폭발적으로 느려지는지 확인합니다.

## 2. 왜 연산 횟수로 비교하는가

두 알고리즘 중 어느 쪽이 빠른지 알고 싶다면 실행 시간을 재 보면 될 것 같습니다. 하지만 실행 시간은 **믿을 만한 비교 기준이 아닙니다.**

- 같은 코드도 **컴퓨터마다** 속도가 다릅니다(스마트폰과 데스크톱).
- 같은 컴퓨터에서도 다른 프로그램이 돌고 있으면 **매번** 달라집니다.
- **언어**(C는 빠르고 Python은 느린 편)에 따라서도 달라집니다.
- 무엇보다 **작은 입력**으로 잰 시간은 큰 입력에서 어떻게 될지 알려 주지 않습니다.

그래서 **"입력 크기 n에 따라 핵심 연산을 몇 번 하는가"** 를 셉니다. 핵심 연산은 알고리즘에서 가장 많이 반복되는 일입니다. 검색이라면 비교, 정렬이라면 비교나 교환입니다. 연산 횟수는 컴퓨터나 언어와 상관없이 **알고리즘 자체의 성질**입니다.

> 이 수업의 모든 예제가 실행 시간 대신 횟수를 출력하는 이유이기도 합니다. 횟수는 어느 컴퓨터에서 실행해도 같아서 검증할 수 있습니다.

## 3. 그림으로 이해하기

입력 크기 n이 커질 때 연산 횟수가 자라는 모양입니다.

```text
연산 횟수
  │                                          O(2ⁿ)  O(n²)
  │                                            │   ╱
  │                                            │  ╱
  │                                            │ ╱
  │                                           ╱│╱       O(n log n)
  │                                         ╱ ╱       ╱
  │                                       ╱ ╱      ╱
  │                                    ╱  ╱     ╱        O(n)
  │                                ╱   ╱    ╱      ___───
  │                          ╱    ╱   ╱  ___───
  │                  ╱     ╱   ___───
  │          ___────___───                                O(log n)
  │   ___───  ______________________________________________
  │ ─────────────────────────────────────────────────────── O(1)
  └──────────────────────────────────────────────────────────── n
```

| 빅오       | 이름      | n = 10 | n = 1,000 |           n = 1,000,000 | 예                              |
| ---------- | --------- | -----: | --------: | ----------------------: | ------------------------------- |
| O(1)       | 상수      |      1 |         1 |                       1 | 배열 인덱스, 해시 맵 조회(평균) |
| O(log n)   | 로그      |      3 |        10 |                      20 | 이진 탐색, 힙 push·pop          |
| O(n)       | 선형      |     10 |     1,000 |               1,000,000 | 선형 탐색, 최댓값 찾기          |
| O(n log n) | 선형 로그 |     33 |    10,000 |              20,000,000 | 병합 정렬, 퀵 정렬(평균)        |
| O(n²)      | 제곱      |    100 | 1,000,000 |       1,000,000,000,000 | 모든 쌍 비교, 삽입 정렬(최악)   |
| O(2ⁿ)      | 지수      |  1,024 |  약 10³⁰¹ | 우주의 원자 수보다 많음 | 모든 부분집합 시도              |

n = 100만일 때 O(log n)은 20번이고 O(n²)은 1조 번입니다. **알고리즘을 바꾸는 것**이 컴퓨터를 바꾸는 것보다 훨씬 큰 차이를 만듭니다.

## 4. 천천히 풀어보기

### 4.1 반복문에서 횟수 세기

코드의 모양으로 횟수를 읽는 기본 규칙입니다.

```text
① 한 겹 반복 (0부터 n-1까지)                  → n번         → O(n)
   for i in range(n): ...

② 두 겹 반복 (둘 다 n번)                      → n × n번     → O(n²)
   for i in range(n):
       for j in range(n): ...

③ 삼각형 반복 (안쪽이 i에 따라 0, 1, ..., n-1번) → n(n-1)/2번  → O(n²)
   for i in range(n):
       for j in range(i): ...

④ 절반씩 줄이기                                → log₂ n번    → O(log n)
   while n > 1: n //= 2

⑤ 연속된 두 반복 (한 겹 + 한 겹)              → n + n번     → O(n)
⑥ 반복 안에서 O(log n) 작업                   → n × log n   → O(n log n)
```

③을 보세요. 정확한 횟수는 n²의 **절반쯤**이지만 여전히 O(n²)입니다. n이 2배가 되면 횟수는 여전히 약 4배가 되기 때문입니다.

### 4.2 빅오의 규칙: 가장 빨리 자라는 항만 남긴다

연산 횟수가 `3n² + 5n + 100`이라고 합시다. n에 따라 각 항의 크기를 비교해 보면,

| n       | 3n²            | 5n      | 100 |
| ------- | -------------- | ------- | --- |
| 10      | 300            | 50      | 100 |
| 1,000   | 3,000,000      | 5,000   | 100 |
| 100,000 | 30,000,000,000 | 500,000 | 100 |

n이 커질수록 **3n²이 나머지를 압도**합니다. 그래서 빅오는 두 가지를 버립니다.

1. **작은 항을 버린다**: 5n과 100은 사라집니다.
2. **상수 배수를 버린다**: 3n²의 3도 버립니다. 3배 차이는 컴퓨터가 조금 빠르거나 느린 정도의 차이라, 알고리즘의 "자라는 모양"과는 관계가 없기 때문입니다.

결과는 **O(n²)** 입니다. 빅오는 "n이 충분히 클 때 이 알고리즘이 **어떤 속도로** 느려지는가"를 알려 주는 표기입니다.

> **주의**: 상수를 버린다고 상수가 중요하지 않은 것은 아닙니다. 같은 O(n)이라도 실제로 10배 빠른 코드가 있습니다. 빅오는 **자라는 모양**을 비교하는 도구이고, 같은 등급 안에서의 차이는 직접 측정해 봐야 합니다.

### 4.3 왜 log가 나오는가

로그 log₂ n은 "n을 몇 번 절반으로 나누면 1이 되는가"입니다. 1,024를 절반씩 나누면 512, 256, …, 2, 1로 **10번**이면 1이 됩니다(2¹⁰ = 1,024). 매번 후보를 절반으로 버리는 알고리즘(이진 탐색, BST 검색, 힙)이 O(log n)인 이유입니다. 입력이 **1,000배** 늘어나도 횟수는 **10번**만 늘어납니다.

### 4.4 최선, 최악, 평균

같은 알고리즘도 **입력의 모양**에 따라 횟수가 다릅니다. 선형 탐색에서

- **최선의 경우**: 찾는 값이 맨 앞 → 1번
- **최악의 경우**: 찾는 값이 없거나 맨 뒤 → n번
- **평균의 경우**: 무작위 위치 → 약 n/2번

특별한 말이 없으면 알고리즘의 복잡도는 **최악의 경우**를 말합니다. "아무리 운이 나빠도 이보다는 빠르다"는 보장이 필요하기 때문입니다. 이 수업의 예제들도 없는 값을 찾게 해서 최악의 경우를 셉니다.

### 4.5 공간 복잡도

시간뿐 아니라 **추가로 쓰는 메모리**도 같은 방법으로 셉니다. 최댓값 찾기는 변수 몇 개만 쓰므로 O(1)이고, 실습의 중복 검사를 집합으로 바꾸면 최대 n개를 저장하므로 O(n)입니다. 이처럼 **메모리를 더 써서 시간을 줄이는** 맞바꿈이 알고리즘 설계에서 자주 등장합니다. 재귀 함수는 호출이 쌓이는 깊이만큼 호출 스택을 쓴다는 점도 기억하세요(Day 24, 64).

### 4.6 입력 크기로 알고리즘 가늠하기

컴퓨터가 **1초에 약 1억(10⁸) 번**의 간단한 연산을 한다고 어림하면, 입력 크기만 보고 어떤 알고리즘이 필요한지 가늠할 수 있습니다.

| 입력 크기 n | 1초 안에 가능한 복잡도        |
| ----------- | ----------------------------- |
| 약 10 ~ 20  | O(2ⁿ), O(n!) (모든 경우 시도) |
| 약 500      | O(n³)                         |
| 약 5,000    | O(n²)                         |
| 약 100만    | O(n log n)                    |
| 약 1억      | O(n)                          |
| 그 이상     | O(log n), O(1)                |

이것은 정확한 규칙이 아니라 **어림셈**입니다. 언어(Python은 C보다 수십 배 느림)와 연산의 종류에 따라 크게 달라집니다. 그래도 "n이 10만인데 O(n²)을 쓰려 한다"는 것을 **코드를 짜기 전에** 알아챌 수 있다는 점이 중요합니다.

## 5. C로 구현하기

C 프로그램은 네 가지 알고리즘의 **핵심 연산 횟수**를 n = 10부터 100,000까지 세어 표로 출력합니다. 찾는 값은 배열에 없는 -1이라서 모두 **최악의 경우**입니다. n = 100,000의 모든 쌍 비교(약 50억 번)는 실제로 세면 오래 걸리므로 공식 n(n-1)/2로 계산했습니다.

```c
// 파일: steps.c
#include <stdio.h>

// 각 함수는 "핵심 연산(비교)"을 몇 번 했는지 돌려준다

long long constant_first(const int a[], int n) {        // O(1)
    (void)a;
    (void)n;
    return 1;                                       // a[0] 한 번 보기
}

long long linear_search(const int a[], int n, int target) {   // O(n)
    long long steps = 0;
    for (int i = 0; i < n; i++) {
        steps++;
        if (a[i] == target) break;
    }
    return steps;
}

long long binary_search(const int a[], int n, int target) {   // O(log n)
    long long steps = 0;
    int lo = 0, hi = n - 1;
    while (lo <= hi) {
        steps++;
        int mid = lo + (hi - lo) / 2;
        if (a[mid] == target) break;
        if (a[mid] < target) lo = mid + 1;
        else hi = mid - 1;
    }
    return steps;
}

long long all_pairs(const int a[], int n) {             // O(n^2)
    long long steps = 0;
    for (int i = 0; i < n; i++) {
        for (int j = i + 1; j < n; j++) {
            steps++;                                // a[i]와 a[j] 비교
            if (a[i] == a[j]) return steps;
        }
    }
    return steps;
}

int data[100000];

int main(void) {
    int sizes[] = {10, 100, 1000, 10000, 100000};
    for (int i = 0; i < 100000; i++) {
        data[i] = 2 * i;                            // 정렬된 서로 다른 짝수
    }
    printf("%8s %6s %10s %8s %12s\n", "n", "O(1)", "O(n)", "O(logn)", "O(n^2)");
    for (int k = 0; k < 5; k++) {
        int n = sizes[k];
        int missing = -1;                           // 없는 값: 최악의 경우
        printf("%8d %6lld %10lld %8lld %12lld\n", n,
               constant_first(data, n),
               linear_search(data, n, missing),
               binary_search(data, n, missing),
               k < 4 ? all_pairs(data, n) : (long long)n * (n - 1) / 2);
    }
    return 0;
}
```

실행 결과:

```text
       n   O(1)       O(n)  O(logn)       O(n^2)
      10      1         10        3           45
     100      1        100        6         4950
    1000      1       1000        9       499500
   10000      1      10000       13     49995000
  100000      1     100000       16   4999950000
```

### 코드 한 부분씩 읽기

| 코드                              | 설명                                                                                                                                                                    |
| --------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `long long steps = 0;`            | 횟수가 50억까지 커지므로 **64비트 정수**를 씁니다. `int`는 약 21억, Windows의 `long`도 32비트라 넘칩니다. `long long`은 어느 환경에서나 최소 64비트입니다(12절 실수 1). |
| `(void)a; (void)n;`               | 쓰지 않는 매개변수에 대한 경고를 없애는 관용구입니다. O(1) 함수는 입력 크기와 상관없이 한 번만 일합니다.                                                                |
| `int mid = lo + (hi - lo) / 2;`   | `(lo + hi) / 2`와 같은 뜻이지만, lo와 hi가 매우 크면 `lo + hi`가 int 범위를 넘을 수 있어 이렇게 씁니다(Day 72에서 자세히).                                              |
| `for (int j = i + 1; j < n; j++)` | 4.1절의 삼각형 반복입니다. 결과 45, 4950, 499500은 모두 n(n-1)/2입니다.                                                                                                 |
| `int data[100000];`               | 40만 바이트 배열을 **전역**으로 두었습니다. 지역 변수로 두면 호출 스택(보통 1~8MB)에 잡혀서 더 큰 배열에서는 스택이 넘칠 수 있습니다.                                   |
| `(long long)n * (n - 1) / 2`      | `n * (n - 1)`을 int로 계산하면 곱하는 순간 넘칩니다. 한쪽을 먼저 `long long`으로 바꿔야 곱셈 전체가 64비트로 계산됩니다.                                                |
| `%6lld`                           | `long long`을 출력하는 형식 지정자입니다. `%d`로 출력하면 정의되지 않은 동작입니다.                                                                                     |

표를 세로로 읽어 보세요. n이 **10배** 커질 때마다 O(n)은 **10배**, O(n²)은 **100배**, O(log n)은 **3~4**만 늘어납니다.

## 6. Python으로 구현하기

Python 프로그램은 4.1절의 반복 모양 네 가지를 직접 세고, 빅오 함수의 값을 공식으로 계산해 증가 속도를 비교합니다. 마지막으로 1초에 1억 번 연산한다고 가정해 걸리는 시간을 어림합니다.

```python
# 파일: growth.py
import math


def count_linear(n):
    steps = 0
    for _ in range(n):              # 한 겹 반복
        steps += 1
    return steps


def count_nested(n):
    steps = 0
    for _ in range(n):              # 두 겹 반복
        for _ in range(n):
            steps += 1
    return steps


def count_halving(n):
    steps = 0
    while n > 1:                    # 매번 절반으로
        n //= 2
        steps += 1
    return steps


def count_triangle(n):
    steps = 0
    for i in range(n):
        for _ in range(i):          # 안쪽이 0, 1, 2, ..., n-1번
            steps += 1
    return steps


print(f"{'n':>5} {'절반씩':>6} {'한 겹':>6} {'삼각형':>7} {'두 겹':>8}")
for n in [8, 16, 32, 64, 128]:
    print(f"{n:>5} {count_halving(n):>6} {count_linear(n):>6} "
          f"{count_triangle(n):>7} {count_nested(n):>8}")

print()
print(f"{'n':>4} {'log2 n':>7} {'n log2 n':>9} {'n^2':>8} {'2^n':>16}")
for n in [10, 20, 30, 40, 50]:
    print(f"{n:>4} {math.log2(n):>7.1f} {n * math.log2(n):>9.0f} {n ** 2:>8} {2 ** n:>16}")

# 초당 1억(10^8)번 연산한다고 할 때 걸리는 시간
ops_per_second = 10 ** 8
n = 100_000
for name, ops in [("O(n)", n), ("O(n log n)", n * math.log2(n)), ("O(n^2)", n ** 2)]:
    print(f"n=100,000에서 {name:<10} → 약 {ops / ops_per_second:.4f}초")
```

실행 결과:

```text
    n    절반씩    한 겹     삼각형      두 겹
    8      3      8      28       64
   16      4     16     120      256
   32      5     32     496     1024
   64      6     64    2016     4096
  128      7    128    8128    16384

   n  log2 n  n log2 n      n^2              2^n
  10     3.3        33      100             1024
  20     4.3        86      400          1048576
  30     4.9       147      900       1073741824
  40     5.3       213     1600    1099511627776

n=100,000에서 O(n log n) → 약 0.0166초
n=100,000에서 O(n^2)     → 약 100.0000초
```

### 코드 한 부분씩 읽기

| 코드                 | 설명                                                                                                                                                                     |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `for _ in range(n):` | `_`는 반복 변수를 쓰지 않는다는 표시입니다. 횟수만 셉니다.                                                                                                               |
| `for _ in range(i):` | 안쪽 반복이 바깥 변수 i에 따라 0, 1, 2, … 번 돕니다. 첫 표의 "삼각형" 열(28, 120, …)은 n(n-1)/2이고, "두 겹" 열(64, 256, …)의 절반보다 조금 작습니다. 둘 다 O(n²)입니다. |
| `n //= 2`            | 정수 나눗셈으로 절반씩 줄입니다. 함수 안의 n은 **지역 변수**라 바깥의 n은 바뀌지 않습니다.                                                                               |
| `math.log2(n)`       | 밑이 2인 로그를 실수로 계산합니다. `:>7.1f`는 7칸에 소수 첫째 자리까지 오른쪽 정렬입니다.                                                                                |
| `2 ** n`             | Python 정수는 크기 제한이 없어서 2⁵⁰도 정확히 계산합니다. C나 Rust였다면 64비트를 넘는 순간 넘칩니다(7절).                                                               |
| `10 ** 8`, `100_000` | 숫자 사이의 `_`는 읽기 쉽게 하는 구분자이고 값에는 영향이 없습니다.                                                                                                      |

두 번째 표에서 n이 10씩 늘 때 n²은 조금씩 늘지만 2ⁿ은 **1,000배씩** 늘어납니다. 지수 시간 알고리즘은 n이 조금만 커져도 쓸 수 없게 됩니다. 마지막 세 줄은 n = 100,000에서 O(n²)이 약 100초, O(n log n)은 0.02초라는 것을 보여 줍니다.

> **참고**: 첫 표의 한글 머리글은 `:>6` 같은 폭을 글자 수로 계산하지만, 화면에서 한글 한 글자는 영문 두 글자만큼 넓어서 줄이 살짝 어긋나 보일 수 있습니다. 숫자 열은 정확히 맞습니다.

## 7. Rust로 구현하기

Rust 프로그램은 이진 탐색의 비교 횟수를 세고, n²과 2ⁿ을 **넘침을 검사하며** 계산합니다. `checked_mul`과 `checked_pow`는 결과가 타입의 범위를 넘으면 `None`을 돌려줍니다.

```rust
// 파일: growth.rs
fn binary_search_steps(sorted: &[u64], target: u64) -> u32 {
    let (mut lo, mut hi) = (0usize, sorted.len());
    let mut steps = 0;
    while lo < hi {
        steps += 1;
        let mid = lo + (hi - lo) / 2;
        if sorted[mid] < target {
            lo = mid + 1;
        } else {
            hi = mid;
        }
    }
    steps
}

fn show(value: Option<u64>) -> String {
    match value {
        Some(v) => v.to_string(),
        None => String::from("넘침!"),
    }
}

fn main() {
    println!("{:>8} {:>6} {:>22} {:>22}", "n", "이진", "n^2", "2^n");
    for n in [10u64, 32, 64, 1_000, 1_000_000] {
        let data: Vec<u64> = (0..n.min(1_000_000)).collect();
        let bin = binary_search_steps(&data, n);        // 없는 값 찾기
        let square = n.checked_mul(n);                   // 넘치면 None
        let power = 2u64.checked_pow(n as u32);
        println!("{:>8} {:>6} {:>22} {:>22}", n, bin, show(square), show(power));
    }
    println!("u64 최댓값: {}", u64::MAX);
}
```

실행 결과:

```text
       n     이진                    n^2                    2^n
      10      3                    100                   1024
      32      5                   1024             4294967296
      64      6                   4096                    넘침!
    1000      9                1000000                    넘침!
 1000000     19          1000000000000                    넘침!
u64 최댓값: 18446744073709551615
```

### 코드 한 부분씩 읽기

| 코드                                             | 설명                                                                                                                                   |
| ------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------- |
| `let (mut lo, mut hi) = (0usize, sorted.len());` | 튜플로 두 변수를 한 번에 만들었습니다. 이 이진 탐색은 hi를 "후보 범위의 끝 다음"으로 쓰는 방식입니다(Day 72에서 두 방식을 비교합니다). |
| `n.checked_mul(n)`                               | 곱셈이 u64 범위를 넘으면 `None`, 아니면 `Some(결과)`입니다. 백만의 제곱(10¹²)은 u64 범위 안이라 계산됩니다.                            |
| `2u64.checked_pow(n as u32)`                     | 2⁶⁴은 u64 최댓값(약 1.8 × 10¹⁹)보다 1 크므로 넘칩니다. 그래서 n = 64부터 "넘침!"입니다. 2³²는 문제없습니다.                            |
| `fn show(value: Option<u64>) -> String`          | 넘침 여부를 문자열로 바꿔 보여 줍니다. Rust는 넘침을 **값으로** 다루게 해서 조용히 틀린 숫자가 나오는 일을 막습니다.                   |
| `(0..n.min(1_000_000)).collect()`                | 0부터 n-1까지의 정렬된 배열을 만듭니다. 이진 탐색으로 n(배열에 없는 값)을 찾아 최악의 경우를 셉니다.                                   |
| `u64::MAX`                                       | u64가 담을 수 있는 가장 큰 값입니다. 2⁶⁴ - 1 = 18,446,744,073,709,551,615입니다.                                                       |

C는 넘치면 **정의되지 않은 동작**(부호 있는 정수)이나 **조용히 돌아가는 값**(부호 없는 정수)이 되고, Python은 넘치지 않고 끝없이 커지며, Rust는 디버그 빌드에서 **panic**하거나 `checked_*`로 **명시적으로** 검사합니다. 연산 횟수처럼 큰 수를 다룰 때는 이 차이를 꼭 기억하세요.

## 8. 실행 추적

4.1절의 삼각형 반복을 n = 5로 따라가며 횟수를 셉니다.

| 바깥 i | 안쪽 j의 범위 | 안쪽 횟수 | 누적 횟수 |
| -----: | ------------- | --------: | --------: |
|      0 | 없음          |         0 |         0 |
|      1 | 0             |         1 |         1 |
|      2 | 0, 1          |         2 |         3 |
|      3 | 0, 1, 2       |         3 |         6 |
|      4 | 0, 1, 2, 3    |         4 |        10 |

합은 0 + 1 + 2 + 3 + 4 = 10 = 5 × 4 / 2입니다. 일반적으로 0 + 1 + ⋯ + (n-1) = n(n-1)/2 = 0.5n² - 0.5n이고, 빅오 규칙으로 작은 항과 상수를 버리면 **O(n²)** 입니다.

## 9. 다른 예제로 다시 이해하기

피보나치 수 F(n) = F(n-1) + F(n-2)를 **정의 그대로** 재귀로 구하면, 같은 값을 **엄청나게 여러 번** 다시 계산합니다. F(5)를 구하려면 F(4)와 F(3)이 필요한데, F(4)를 구하는 중에 또 F(3)을 구합니다. 호출이 두 갈래로 계속 나뉘므로 호출 횟수는 대략 1.6ⁿ씩 늘어나는 **지수 시간**입니다. 반면 반복문으로 앞의 두 값을 들고 가면 n번이면 끝납니다(**선형 시간**). 같은 문제를 푸는 두 알고리즘이 n = 25에서 **약 24만 번**과 **25번**으로 차이 납니다. Day 79의 동적 계획법은 이런 중복 계산을 없애는 방법입니다.

```python
# 파일: fib_calls.py
calls = 0


def fib_recursive(n):
    global calls
    calls += 1
    if n < 2:
        return n
    return fib_recursive(n - 1) + fib_recursive(n - 2)


def fib_loop(n):
    a, b, steps = 0, 1, 0
    for _ in range(n):
        a, b = b, a + b
        steps += 1
    return a, steps


for n in [10, 20, 25]:
    calls = 0
    value = fib_recursive(n)
    loop_value, steps = fib_loop(n)
    print(f"F({n}) = {value:>6}  재귀 호출 {calls:>7}번 / 반복 {steps:>2}번, 같은 값? {value == loop_value}")
```

실행 결과:

```text
F(10) =     55  재귀 호출     177번 / 반복 10번, 같은 값? True
F(20) =   6765  재귀 호출   21891번 / 반복 20번, 같은 값? True
F(25) =  75025  재귀 호출  242785번 / 반복 25번, 같은 값? True
```

n이 5 늘 때마다 재귀 호출은 약 11배씩 늘어납니다. Rust로 같은 실험을 하면 결과가 똑같습니다. 호출 횟수를 전역 변수 대신 `&mut` 매개변수로 넘겨 세는 방법을 보세요.

```rust
// 파일: fib_calls.rs
fn fib_recursive(n: u64, calls: &mut u64) -> u64 {
    *calls += 1;
    if n < 2 {
        return n;
    }
    fib_recursive(n - 1, calls) + fib_recursive(n - 2, calls)
}

fn fib_loop(n: u64) -> u64 {
    let (mut a, mut b) = (0u64, 1u64);
    for _ in 0..n {
        (a, b) = (b, a + b);
    }
    a
}

fn main() {
    for n in [10, 20, 25, 30] {
        let mut calls = 0;
        let value = fib_recursive(n, &mut calls);
        println!("F({n}) = {value}, 재귀 호출 {calls}번, 반복 결과 {}", fib_loop(n));
    }
}
```

실행 결과:

```text
F(10) = 55, 재귀 호출 177번, 반복 결과 55
F(20) = 6765, 재귀 호출 21891번, 반복 결과 6765
F(25) = 75025, 재귀 호출 242785번, 반복 결과 75025
F(30) = 832040, 재귀 호출 2692537번, 반복 결과 832040
```

F(30)은 재귀로 약 270만 번 호출합니다. F(50)을 재귀로 구하면 약 400억 번이라 컴퓨터가 몇 분씩 계산해야 하지만, 반복문은 50번이면 됩니다.

## 11. 세 언어 비교

| 관점                 | C                                       | Python                            | Rust                                      |
| -------------------- | --------------------------------------- | --------------------------------- | ----------------------------------------- |
| 큰 횟수를 담을 정수  | `long long` (Windows의 `long`은 32비트) | `int` (크기 제한 없음)            | `u64`, `i64`, 필요하면 `u128`             |
| 넘치면               | 부호 있는 정수는 정의되지 않은 동작     | 넘치지 않음(메모리가 허락하는 한) | 디버그 빌드는 panic, `checked_*`는 `None` |
| 같은 알고리즘의 속도 | 가장 빠른 편                            | 수십 배 느린 편                   | C와 비슷                                  |
| 연산 횟수            | 같다                                    | 같다                              | 같다                                      |

마지막 줄이 핵심입니다. 언어마다 실행 속도는 달라도 **연산 횟수와 빅오는 같습니다.** O(n²) 알고리즘은 C로 짜도 n이 커지면 느리고, O(n log n) 알고리즘은 Python으로 짜도 빠릅니다.

## 12. 자주 하는 실수

### 실수 1: 큰 횟수를 `int`나 `long`으로 센다

실습의 디버그 문제입니다. n = 10만의 쌍 수는 약 50억이라 32비트 `int`의 범위(약 21억)를 넘습니다. C에서 부호 있는 정수가 넘치면 **정의되지 않은 동작**이고, Windows에서는 `long`도 32비트입니다. 이 수업을 준비하면서 처음 쓴 C 코드도 `long`을 써서 리눅스에서는 맞고 Windows에서는 704982704라는 엉뚱한 값을 출력했습니다. **어느 환경에서나 64비트가 보장되는 `long long`** (또는 `<stdint.h>`의 `int64_t`)을 쓰세요.

### 실수 2: 반복문 안에 숨은 반복을 놓친다

```c
for (int i = 0; i < strlen(s); i++) { ... }   // strlen이 매번 문자열 전체를 센다
```

반복 조건의 `strlen(s)`는 부를 때마다 O(n)입니다. 반복이 n번 돌면 전체가 O(n²)이 됩니다. Python의 `x in some_list`, `list.pop(0)`, `list.insert(0, x)`도 한 줄이지만 O(n)입니다. **함수 호출과 연산자의 비용**도 세어야 합니다.

### 실수 3: 두 겹 반복이면 무조건 O(n²)이라고 생각한다

```python
# 파일: not_quadratic.py
steps = 0
n = 1024
i = 1
while i < n:
    for _ in range(8):        # 안쪽은 항상 8번
        steps += 1
    i *= 2                    # 바깥은 절반씩이 아니라 두 배씩
print(steps)
```

실행 결과:

```text
80
```

바깥 반복은 i를 두 배씩 늘리므로 log₂ 1024 = 10번, 안쪽은 항상 8번이라 80번입니다. O(8 log n) = O(log n)이지 O(n²)이 아닙니다. 반복의 **겹 수가 아니라 각 반복이 몇 번 도는지**를 세야 합니다.

### 실수 4: 작은 입력으로만 시험한다

n = 10에서는 O(n²) 알고리즘도 100번이라 순식간에 끝납니다. 문제는 실제 데이터가 10만 개일 때입니다. 알고리즘을 고를 때는 **실제로 들어올 입력의 최대 크기**를 먼저 확인하고 4.6절의 표로 가늠하세요.

### 실수 5: 빅오가 같으면 속도도 같다고 생각한다

O(n)인 두 알고리즘 중 하나는 원소마다 연산 1번, 다른 하나는 100번을 할 수도 있습니다. 빅오는 **자라는 모양**만 알려 줍니다. 같은 등급끼리의 비교는 실제로 측정해야 합니다. 반대로 빅오가 다르면 n이 충분히 커졌을 때 **반드시** 차이가 납니다.

## 13. Q&A

**Q. 빅오(O), 빅오메가(Ω), 빅세타(Θ)는 무엇이 다른가요?**

A. 엄밀히 말하면 O는 "이보다 빠르게 자라지 않는다(상한)", Ω는 "이보다 느리게 자라지 않는다(하한)", Θ는 "딱 이만큼 자란다"는 뜻입니다. 실무와 대부분의 수업에서는 O를 Θ처럼 "대략 이만큼"이라는 뜻으로 씁니다. 이 수업도 그렇게 씁니다.

**Q. O(log n)의 로그 밑은 2인가요, 10인가요?**

A. 빅오에서는 상관없습니다. log₂ n과 log₁₀ n은 약 3.3배 차이인데, 상수 배수는 버리기 때문입니다. 그래도 절반씩 나누는 알고리즘을 생각할 때는 log₂로 어림하는 것이 편합니다.

**Q. 해시 맵은 O(1)인데 왜 항상 해시 맵을 쓰지 않나요?**

A. 해시 맵의 O(1)은 **평균**이고, 해시 계산이라는 상수 비용이 있으며, 순서와 범위 검색을 못 합니다(Day 67). 원소가 적으면 배열을 훑는 것이 더 빠르기도 합니다. 복잡도는 여러 판단 기준 중 하나입니다.

**Q. 실제 시간을 재고 싶다면 어떻게 하나요?**

A. Python은 `time.perf_counter()`나 `timeit` 모듈, Rust는 `std::time::Instant`, C는 `<time.h>`의 `clock()`을 씁니다. 여러 번 재서 평균을 내고, 입력 크기를 바꿔 가며 **몇 배로 늘어나는지**를 보면 빅오를 실험으로 확인할 수 있습니다. 이 수업의 예제가 시간을 출력하지 않는 이유는 실행할 때마다 값이 달라서 검증할 수 없기 때문입니다.

## 14. 핵심 요약

- 알고리즘은 실행 시간이 아니라 **입력 크기 n에 따른 핵심 연산 횟수**로 비교합니다.
- 빅오는 **가장 빨리 자라는 항**만 남기고 **상수 배수를 버린** 표기입니다. 3n² + 5n + 100 → O(n²).
- 한 겹 반복 O(n), 두 겹·삼각형 반복 O(n²), 절반씩 줄이기 O(log n), 반복 안의 로그 O(n log n), 두 갈래 재귀는 지수 시간입니다.
- 특별한 말이 없으면 **최악의 경우**를 말합니다. **공간 복잡도**도 함께 따지며, 공간을 써서 시간을 줄이기도 합니다.
- 1초에 약 10⁸번이라고 어림하면 **입력 크기로 필요한 알고리즘**을 미리 가늠할 수 있습니다.
- 큰 횟수를 셀 때 C는 `long long`, Rust는 `u64`와 `checked_*`를 쓰고, Python은 넘치지 않습니다.
