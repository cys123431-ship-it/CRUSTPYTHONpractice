## 오늘 배울 이유

주소 공유와 독립 복사를 손으로 구분하고 수명에 따라 안전한 방법을 선택합니다. Day 42 "`메모리 모델 종합 회상`"에서는 Python 코드의 실행 결과(`[1] [1, 2]`)를 따라가며, `복사 범위와 공유 상태 확인` 동작이 왜 필요한지 확인합니다. 이 동작이 빠지면 "`얕은 복사를 중첩 리스트의 깊은 복사로 착각함`" 같은 문제가 생깁니다.

## 시작 전에 확인할 것

바로 앞선 [Day 41](/learn/day-41-box)에서 배운 "Rust Box와 힙 소유" 내용을 한 문장으로 말해 보세요. 이번 "`메모리 모델 종합 회상`"에서 새로 달라지는 조건을 찾아보세요. 핵심 표현은 `a.copy()`입니다.

## 머릿속 그림

b는 새 바깥 리스트를 소유한 참조이므로 append는 a를 바꾸지 않습니다. Day 42에서는 아래 흐름 순서대로 상태가 바뀌고, 결과를 가르는 부분은 `a.copy()`입니다.

```text
a=[1]  →  b=[1] 별도 객체  →  b=[1,2]
```

위 흐름에서 `a.copy()` 부분이 실행되는 지점을 찾으면 읽는 값과 바뀌는 값이 나뉘어 보입니다. 마지막 출력은 `[1] [1, 2]`입니다.

## 천천히 풀어보기

메모리 학습에서 먼저 물을 것은 '어느 이름이 어떤 데이터를 가리키는가'입니다. `b = a.copy()` 뒤 `b.append(30)`은 바깥 리스트가 달라서 `a`를 바꾸지 않습니다. `b = a`였다면 두 이름이 같은 리스트를 보므로 `a`에서도 추가한 값이 보입니다.

한 줄씩 실행하며 `a → 리스트1`, `b → 리스트2`처럼 종이에 그려 보세요. C 포인터는 유효한 주소를 직접 다뤄야 하고, Rust의 소유권은 유효하지 않은 참조 사용을 막는 규칙을 제공합니다. 같은 '참조'라는 말을 들어도 언어마다 허용되는 동작이 다릅니다.

## 문법을 예제로 보기

아래 Python 코드는 Day 42 "`메모리 모델 종합 회상`"의 독립 예제입니다. 전체 4줄 가운데 핵심 부분은 `a.copy()`이며, 실행 결과는 `[1] [1, 2]`입니다.

```python
a = [1]
b = a.copy()
b.append(2)
print(a, b)
```

예상 출력:

```text
[1] [1, 2]
```

하단 Python 실행 영역에 같은 코드가 들어 있습니다. 먼저 실행 결과(`[1] [1, 2]`)를 가리고 예측한 뒤 실행해 비교하세요.

## 핵심 줄 따라 읽기

예제의 핵심 표현은 `a.copy()`입니다. 아래 줄 번호가 붙은 코드에서 이 표현이 있는 줄을 찾으세요.

```python
 1 | a = [1]
 2 | b = a.copy()
 3 | b.append(2)
 4 | print(a, b)
```

1. a=[1]입니다
2. copy로 b=[1]을 새로 만듭니다
3. b만 [1,2]가 되어 함께 출력합니다

`a.copy()` 부분이 실행될 때 읽는 값과 바뀌는 값을 한 줄씩 적어 보세요. 다음 `결과 예측과 작은 변경`에서는 이 부분이 달라집니다.

## 실행 추적

| 순서 | 상태 또는 동작  |
| ---: | --------------- |
|    1 | a=[1]           |
|    2 | b=[1] 별도 객체 |
|    3 | b=[1,2]         |

위 순서대로 실행한 최종 출력은 `[1] [1, 2]`입니다. `a=[1]` 단계와 마지막 단계를 비교하면 입력과 출력의 관계가 보입니다.

## 다른 예제로 다시 이해하기

`a=[[1]]; b=a.copy(); b[0].append(2)`이면 a까지 `[[1,2]]`가 됩니다. 이번엔 `b.append([3])`을 더하면 a는 그대로 `[[1,2]]`, b만 `[[1,2],[3]]`입니다. 같은 얕은 복사여도 **안쪽 객체 수정**과 **바깥 리스트 추가**는 다른 결과를 냅니다.

## 결과 예측과 작은 변경

원본 실행 결과는 `[1] [1, 2]`입니다. 아래 코드에서 원본과 다른 줄을 먼저 찾으세요.

```python
a = [2]
b = a.copy()
b.append(2)
print(a, b)
```

찾은 줄을 적용했을 때의 실행 결과를 먼저 예측해 보세요.

해설: 바뀐 코드의 실행 결과는 아래와 같습니다.

```text
[2] [2, 2]
```

원본과 달라졌습니다. 원본 출력은 `[1] [1, 2]`입니다. 다른 줄(`a = [1]` → `a = [2]`)에서 시작된 차이가 이후 흐름을 타고 최종 출력에 반영되었습니다. 원본 추적(`a=[1]` → …)과 바뀐 줄부터 대조해 보세요.

## 자주 틀리는 지점

**확인할 실수: 얕은 복사를 중첩 리스트의 깊은 복사로 착각함.** 정상 코드의 실행 결과는 `[1] [1, 2]`입니다.

- 정상 줄: `b = a.copy()`
- 잘못된 줄: `b = a`

두 줄을 나란히 놓고 `b는 새 바깥 리스트를 소유한 참조이므로 append는 a를 바꾸지 않습니다.` 기준으로 어느 쪽이 맞는지 설명하세요. 결과가 예상과 다르면 `a=[1]`부터 `[1] [1, 2]`까지 처음 어긋난 곳을 찾습니다.

## 다른 언어로 옮기기

세 언어에서 지켜야 할 핵심 동작은 `복사 범위와 공유 상태 확인`입니다. 목표는 같은 입력에 같은 결과를 내는 것으로, 각 언어의 규칙에 맞게 옮겼는지 실행 결과로 대조하세요.

| 언어   | 옮길 때 확인할 표현과 규칙               |
| ------ | ---------------------------------------- |
| C17    | 포인터 주소 복사와 버퍼 내용 복사는 다름 |
| Python | list.copy는 중첩 원소까지 복제하지 않음  |
| Rust   | clone의 구현이 무엇을 복사하는지 확인    |

C17에서는 `포인터 주소 복사와 버퍼 내용 복사는 다름` 규칙을 적용합니다. "`메모리 모델 종합 회상`" 수업의 실행 결과(`[1] [1, 2]`)를 기준으로 삼고, C는 범위와 널 검사를 자동으로 해 주지 않으므로, 코드에 사용된 접근마다 유효 범위를 직접 확인해야 합니다. Python에서는 `list.copy는 중첩 원소까지 복제하지 않음` 규칙을 따릅니다. 실패나 빈 입력은 예외로 드러내며 조용히 넘기지 마세요. Rust에서는 `clone의 구현이 무엇을 복사하는지 확인` 규칙을 따릅니다. 실행 결과가 다르면 컴파일 오류(타입, 소유권, 빌림)와 실행 때 패닉(인덱스 범위 등) 중 어느 쪽인지 메시지부터 구분하세요.
