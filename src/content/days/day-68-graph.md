## 오늘 배울 이유

한 항목이 여러 항목과 연결될 때 트리의 단일 부모 규칙보다 일반적인 그래프가 필요합니다. Day 68 "`그래프의 인접 목록`"에서는 Python 코드의 실행 결과(`['B', 'C']`)를 따라가며, `정점별 이웃 표현` 동작이 왜 필요한지 확인합니다. 이 동작이 빠지면 "`방향 간선을 역방향에도 자동으로 있다고 간주함`" 같은 문제가 생깁니다.

## 시작 전에 확인할 것

## 머릿속 그림

인접 목록은 정점마다 바로 이어진 이웃의 목록을 저장합니다. 방향 그래프라면 A→B가 B→A를 뜻하지 않습니다. Day 68에서는 아래 흐름 순서대로 상태가 바뀌고, 결과를 가르는 부분은 `["A"]`입니다.

```text
A → B,C  →  B → C  →  A 이웃 B,C
```

위 흐름에서 `["A"]` 부분이 실행되는 지점을 찾으면 읽는 값과 바뀌는 값이 나뉘어 보입니다. 마지막 출력은 `['B', 'C']`입니다.

## 천천히 풀어보기

그래프는 정점과 정점 사이의 연결을 나타냅니다. `edges["A"] = ["B","C"]`라면 A에서 바로 갈 수 있는 곳은 B와 C입니다. 이웃 목록에는 **한 번 건너가서 도착할 수 있는 정점**만 적고 먼 정점은 탐색으로 찾습니다.

방향 있는 그래프에서 A→B라고 해서 B→A가 생기지는 않습니다. 양방향 도로라면 양쪽 목록에 모두 기록해야 합니다. 연결이 전혀 없는 정점도 키에 빈 리스트로 넣어 두면 탐색할 때 빠뜨리지 않습니다. 순서가 의미 있는지도 문제에 따라 정하세요.

## 문법을 예제로 보기

아래 Python 코드는 Day 68 "`그래프의 인접 목록`"의 독립 예제입니다. 전체 2줄 가운데 핵심 부분은 `["A"]`이며, 실행 결과는 `['B', 'C']`입니다.

```python
edges = {"A": ["B", "C"], "B": ["C"], "C": []}
print(edges["A"])
```

예상 출력:

```text
['B', 'C']
```

## 핵심 줄 따라 읽기

예제의 핵심 표현은 `["A"]`입니다. 아래 줄 번호가 붙은 코드에서 이 표현이 있는 줄을 찾으세요.

```python
 1 | edges = {"A": ["B", "C"], "B": ["C"], "C": []}
 2 | print(edges["A"])
```

1. A의 이웃을 B,C로 등록합니다
2. B의 이웃은 C입니다
3. A 목록을 읽어 두 이웃을 출력합니다

`["A"]` 부분이 실행될 때 읽는 값과 바뀌는 값을 한 줄씩 적어 보세요. 다음 `결과 예측과 작은 변경`에서는 이 부분이 달라집니다.

## 실행 추적

| 순서 | 상태 또는 동작 |
| ---: | -------------- |
|    1 | A              |
|    2 | B,C            |
|    3 | B              |
|    4 | C              |
|    5 | A 이웃 B,C     |

위 순서대로 실행한 최종 출력은 `['B', 'C']`입니다. `A` 단계와 마지막 단계를 비교하면 입력과 출력의 관계가 보입니다.

## 다른 예제로 다시 이해하기

`A:[B,C]`, `B:[C]`, `C:[]`라면 A에서 B와 C로 바로 갈 수 있고 B에서도 C로 갈 수 있습니다. 그러나 C에서 A로 가는 간선은 적혀 있지 않습니다. **길이 2인 경로 A→B→C**와 **직접 간선 A→C**를 구별해 보세요.

## 시간과 공간 복잡도

인접 목록에서 A의 이웃을 읽으면 차수만큼 걸려 O(차수)입니다. 전체 간선 보관 공간은 O(정점+간선)입니다. A→B→C 길이 2 경로와 직접 간선 A→C를 구별하세요. 적혀 있지 않은 C→A 방향으로는 갈 수 없습니다. Day 68의 핵심 연산을 위 기준으로 직접 세어 보세요.

원본 실행 결과는 `['B', 'C']`입니다. 아래 코드에서 원본과 다른 줄을 먼저 찾으세요.

```python
edges = {"A": ["B", "C"], "B": ["C"], "C": []}
print(edges["B"])
```

찾은 줄을 적용했을 때의 실행 결과를 먼저 예측해 보세요.

해설: 바뀐 코드의 실행 결과는 아래와 같습니다.

```text
['C']
```

원본 출력은 `['B', 'C']`이고, 바뀐 코드의 실행 결과는 `['C']`입니다. 바뀐 줄은 `print(edges["A"])`에서 `print(edges["B"])`로 바뀌었습니다. 바뀐 프로그램은 `A` 단계에서 시작해 바뀐 줄에서 다른 중간 값을 만들고, 이후 흐름을 따라 최종 `['C']`가 됩니다. 원본 추적 `A → B,C  →  B → C  →  A 이웃 B,C`에서 바뀐 줄 이후 단계와 하나씩 비교하면 처음 달라지는 곳이 보입니다.

## 자주 틀리는 지점

**확인할 실수: 방향 간선을 역방향에도 자동으로 있다고 간주함.** 정상 코드의 실행 결과는 `['B', 'C']`입니다.

- 정상 줄: `print(edges["A"])`
- 잘못된 줄: `print(edges["C"])`

두 줄을 나란히 놓으면 정상 줄 `print(edges["A"])`이 `인접 목록은 정점마다 바로 이어진 이웃의 목록을 저장합니다. 방향 그래프라면 A→B가 B→A를 뜻하지 않습니다.` 설명과 맞고, 잘못된 줄은 `방향 간선을 역방향에도 자동으로 있다고 간주함` 쪽으로 어긋납니다. 결과가 예상과 다르면 `A`부터 `['B', 'C']`까지 처음 어긋난 곳을 찾습니다.

## 다른 언어로 옮기기

세 언어에서 지켜야 할 핵심 동작은 `정점별 이웃 표현`입니다. 목표는 같은 입력에 같은 결과를 내는 것으로, 각 언어의 규칙에 맞게 옮겼는지 실행 결과로 대조하세요.

| 언어   | 옮길 때 확인할 표현과 규칙   |
| ------ | ---------------------------- |
| C17    | 정점 인덱스와 동적 이웃 배열 |
| Python | dict[str,list[str]]          |
| Rust   | HashMap<&str,Vec<&str>>      |

C17에서는 `정점 인덱스와 동적 이웃 배열` 규칙을 적용합니다. "`그래프의 인접 목록`" 수업의 실행 결과(`['B', 'C']`)를 기준으로 삼고, C는 범위와 널 검사를 자동으로 해 주지 않으므로, 코드에 사용된 접근마다 유효 범위를 직접 확인해야 합니다. Python에서는 `dict[str,list[str]]` 규칙을 따릅니다. 실패나 빈 입력은 예외로 드러내며 조용히 넘기지 마세요. Rust에서는 `HashMap<&str,Vec<&str>>` 규칙을 따릅니다. 실행 결과가 다르면 컴파일 오류(타입, 소유권, 빌림)와 실행 때 패닉(인덱스 범위 등) 중 어느 쪽인지 메시지부터 구분하세요.
